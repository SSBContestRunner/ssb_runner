badge 放在哪里？

文档待确认 #1：顶栏图标，还是会话卡片头部的小圆点？两者都不阻断开赛、都只做提示，差别是可见范围与布局代价。

待决
A · 顶栏常驻图标 文档当前方案
顶栏右侧 · 主题与设置之间 · 40×40
异常时只替换图标与颜色，右侧图标不位移；正常态保留弱化占位。
+常驻可见：待机、比赛中都在，不依赖会话卡片滚动位置。
+与设置红点共用“全局状态”位置，语义统一。
−离 RUN 较远，开赛瞬间注意力在卡片右下。
−顶栏图标从 3 个增至 4 个（含设置）。
B · 会话卡片头部圆点 备选
会话卡片头部 · 状态 chip 右侧 · 8dp 圆点
本轮训练 就绪
CQ WW DX · 比赛 · 20 分钟
圆点只表达“有问题”，点击后才展开原因；不占顶栏。
+紧邻状态 chip 与 RUN，开赛前最容易被看到。
+不增加顶栏元素，保持现有顶栏节奏。
−卡片头部宽度预算已用于标题 / 状态 chip / 复盘胶囊，加元素会挤压标题。

D2

正常态要不要显示？

文档待确认 #2：正常时保留弱化的音量图标，还是完全不显示？用下面的“预览异常”看切换瞬间的布局代价。

待决
A · 保留弱化图标 文档当前方案
正常态 · 55% 不透明度
切换时仅图标与颜色变化，右侧设置按钮位置不变。
+布局稳定：异常/恢复都不会推动右侧图标。
+保留“音频在哪里”的可发现性，新用户能猜到。
−常驻多一个图标，顶栏视觉噪音略高。
B · 正常态完全隐藏 备选
正常态 · 不占位
异常出现时，右侧 3 个图标整体左移 40dp，恢复时再移回来。
正常态更干净，但问题出现前用户不知道这里有音频状态。
+正常态最“小”，顶栏更干净。
−出现/消失时右侧图标与设置按钮整体位移（40dp）。
−可发现性差：新用户不知道此处会出现音频状态。

轮询间隔能不能接受？

文档待确认 #3：2s（macOS/Windows）/ 3s（Linux）是否可接受，还是必须上事件驱动？点“模拟系统静音”看提示延迟。

待决
提示出现时间线 假设 t=0 时系统被静音，badge 在下列时刻出现
轮询 2s macOS / Windows · 原生属性读取，微秒级 —
badge 出现
轮询 3s Linux · 每轮 fork 一个 pactl/wpctl 进程，5–15ms —
badge 出现
事件驱动 CoreAudio 属性监听 / WASAPI Notify / pactl subscribe —
badge 出现
A · P0 只做轮询：2s / 3s 文档当前方案
满足“实时”的体感（≤3s），实现最省；事件驱动留到 P0-c 再替换同一 probe 接口。
B · P0 直接上事件驱动，轮询兜底
延迟 <0.5s，但三平台各写一套监听器，且监听失效仍需轮询，P0 工作量显著增加。
C · 统一放长到 5s，进一步省开销
CPU / fork 最少，但比赛中调音量后可能错过一整道题，与“实时”目标冲突。

B · 仅生成双音（700Hz → 1000Hz） 备选
设置 → 声音
80%

生成：700Hz → 1000Hz，30ms 淡入淡出
不依赖任何资源文件，永远可播。
+不依赖资源，代码最简单，失败路径少。
+任何平台、任何安装方式都一定能播。
−只能证明“链路通”，不能证明“素材能解码”。
−听感与真实呼叫差异大，用户可能误判音量。
