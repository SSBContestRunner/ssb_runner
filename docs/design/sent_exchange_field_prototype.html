03

状态时序

顶部「状态」可切换，高亮行跟随原型
阶段状态显示值理由
待机—001（下一局第 1 个）不沿用上一局的列表长度
发送中ReportMyExchange本局行数 + 1尚未落库，与正在发送的值相同
等待对方交换WaitingSubmitMyExchange本局行数 + 1尚未落库，仍与实发值相同
落库后收尾QsoEnd / SpQsoEnd行数 + 1（下一个）立即指向下一个序号（D3 已定：不冻结）

序号口径必须与本局原始行数（含 DUPE）一致，不能用 uniqueQsos 的计数，否则 WPX 会与实发值偏移。落库后字段立刻指向下一个序号，与 N1MM 的下一序号显示一致。

04

决策记录

决策已固化，原型按最终结论运行
D1标签命名已确定 A

采用「对方交换 / 我方交换」对称命名（英文 Rcvd / Sent，日文 受信交換 / 送信交換）。日志表头同步改为「对方交换」。

已应用于本原型
D2是否包含 RST已确定 独立

RST 保持独立，固定 59，与 SendNr 一样置灰；buildMyExchange 只返回 RST 之后的部分，避免重复 59。

已应用于本原型
D3WPX 序号时序已确定 不冻结

字段始终等于 buildMyExchange(本局行数 + 1)，即下一个 QSO 要发的序号，与 _myExchange() 同一口径，零状态耦合。

已应用于本原型
D4设置页发射预览已确定 加

在我的电台下方显示「发射内容：59 05」，把设置里录入的 5 与实际播报的 05 连起来。预览块与上方字段保持 16px 间距（MD3），CQ WPX 的序号提示与预览之间同样 16px。

已应用于本原型
D5锁定图标跳设置已确定 加

点击锁定图标深链到设置页对应字段；运行中禁用点击，tooltip 改为「比赛进行中无法修改；停止后可改」。

已应用于本原型
D6写入 QSO 记录已确定 不写入

不新增 QsoTable 列；日志表第 4 列「交换信息」改名为「对方交换」，明确它记录的是收到的一方。

已应用于本原型
D7字段顺序与宽度已确定

固定为 Call → RST → 我方交换 → 对方交换；RST 与我方交换窄栏、置灰、不可聚焦，主要宽度（约 75%）留给 Call 与对方交换。

已应用于本原型
D8固定交换是否显示已确定 始终显示

固定四栏意味着 SendNr 始终存在（D8 按“显示”落定）。N1MM 只在可变交换时显示 SentNr；本 App 为训练保留常显。
