# v0.3.0 固定口音（Incoming Accent）方案

> 调研时间：2026-10-28
> 目标：允许用户把「来台口音」固定为某一个（例如 US），用于针对性听力训练；默认行为保持不变。
> 相关说明：v0.3.0 不做语音包压缩 / 按口音拆包，现有 6 组语音资源（含 `Global`）全部随安装包分发，各口音在资源层面始终可用。

---

## 0. 结论（TL;DR）

1. **现状**：口音完全由来台的 DXCC 实体决定（`obtainAccentByDxccId`），用户自己的声音固定用 `Global`（中性 ICAO 组）。
2. **方案**：新增用户设置 `Incoming accent ∈ {Auto, US, UK, JP, RU, IN}`，默认 `Auto`（严格保持现有行为）。
3. **实现要点**：把「按 DXCC 选口音」抽成 `AccentPolicy.resolve(isMe, dxccId)`，替换 `obtainAssetDir(...)` 等散落调用（实测 **10 处来台调用**；另有 16 处 `myAudioAccentDir` 本台调用保持不变），避免在调用点直接读全局设置。
4. **自己的声音保持 `Global`**，不随该设置变化。理由：它是「本台」的参考发音，且 `Global` 必须始终随包分发（兜底资源），改动收益小、回归面大。
5. **可复现性**：口音只影响音频资源，不影响题目生成（题目由 `questionSeed` 决定）。但为了让回放/复盘听到同一口音，需把 `accentId` 记入 `TrainingRunMetadata`，并向后兼容旧记录（缺省 `auto`）。
6. **训练公平性**：固定口音会让难度更稳定（少一种变化），应在成绩上传时附带 `accentId`，但**不建议 v0.3.0 就拆榜**；先记录、后观察。
7. **语音包分发**：v0.3.0 不做压缩与按口音拆包，全部语音资源随包分发，因此固定口音**不引入下载或回退逻辑**；若未来拆包，再按 §4.6 补充下载与提示。

## 1. 现状梳理

### 1.1 口音映射

`lib/audio/audio_loader.dart` 中的映射是硬编码的实体列表：

| 口音目录 | 判定 | 说明 |
|---|---|---|
| `JP` | DXCC ∈ {339, 177, 192} | 日本及其相关实体 |
| `RU` | DXCC ∈ {54, 126, 15, 288, 27, 130, 292} | 俄语区 |
| `UK` | DXCC ∈ {223, 279, 294, 265, 114, 122, 106, 150, 35, 38, 147, 189, 170, 34, 133, 1} | 英式英语区 |
| `IN` | 南亚 + 东南亚实体集合 | 印度英语/东南亚口音 |
| `US` | **兜底**（其他所有实体） | 美式英语 |
| `Global` | 仅用于「本台」与兜底片段 | 中性 ICAO 发音 + 通用词 |

- 「本台」始终使用 `Global`（`myAudioAccentDir`），因此用户自己的 CQ/呼号发音不随实体变化。
- 口音**只影响音频资源选择**：`AudioLoader.loadAudio(accentDir, payload)`；题目、呼号、交换信息由 `questionSeed` 决定，与口音无关。
- `PhonicType.mixed` 的随机选择由 `SessionRandom` 驱动，同样与口音无关；固定口音不会破坏练习种子的可复现性。

### 1.2 调用点分布

| 位置 | 调用方式 | 性质 |
|---|---|---|
| `lib/audio/payload_to_audio.dart` | `obtainAssetDir(isMe, dxccId)` | 对外统一入口，内部直接调用映射 |
| `lib/contest_run/new/contest_state_change_handler.dart` | `obtainAccentByDxccId(...)`、`obtainAssetDir(false, dxccId)`、`myAudioAccentDir` | **10 处来台** + 5 处本台 |
| `lib/contest_run/new/contest_operation_event_handler.dart` | `myAudioAccentDir` | 本台按键音，11 处（不涉及来台口音） |

**结论**：需要改的是「来台」路径；`myAudioAccentDir` 常量调用**不应**被替换，否则会把本台声音也改掉。

### 1.3 语音资源覆盖度（决定固定口音是否可用）

| 目录 | 文件数 | 分类覆盖 |
|---|---|---|
| `Global` | 65 | Common 9、ICAO 26、Number 30 |
| `US` / `UK` / `JP` / `IN` | 99 | Common 8、Alphabet 9、ICAO 26、Location 26、Number 30 |
| `RU` | 98 | Common **7**（缺 1），其余同上 |

- 缺失片段由现有兜底逻辑处理：`Common/Number` → `Global`；`Location/Alphabet` → 同口音 `ICAO`；`ICAO` → `Global ICAO`。
- 因此固定任意一种口音在**资源层面是完整的**（RU 的 1 个 Common 缺口会自动回退）。

## 2. 需求与目标

| 编号 | 需求 |
|---|---|
| A1 | 用户可在设置中选择来台口音：Auto / US / UK / JP / RU / IN |
| A2 | 默认 `Auto`，与 v0.2.0 行为完全一致 |
| A3 | 设置持久化，重启后保留 |
| A4 | 训练进行中不可修改（与现有设置一致） |
| A5 | 选择后，所有来台（非本台）音频使用该口音；本台保持 `Global` |
| A6 | 口音记录进成绩元数据，复盘/上传/回放可追溯 |
| A7 | 资源缺失时有确定的降级行为（回退 + 提示），不静默失败 |
| A8 | 不改变题目生成、计分与练习种子的可复现性 |

**非目标**：按台随机口音、按频段/地区细分口音、用户自定义口音包、本台口音设置。

## 3. 方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 全局策略对象（推荐）** | 新增 `IncomingAccent` 枚举 + `AccentPolicy`，注入音频调用链 | 调用点集中、可测试、行为清晰 | 需要改约 15 处调用 | **采用** |
| B. 在 `obtainAssetDir` 里读全局单例设置 | 少改代码 | 隐式依赖、测试需 mock 全局状态、音频层耦合设置层 | 长期维护差 | 不采用 |
| C. 每局开始时把口音写进会话状态 | 与种子一起传递 | 与现有 session profile 风格一致 | 仍需替换调用点，收益同 A | 可作为 A 的实现细节 |
| D. 每台随机口音 | 不需要设置 | 更接近真实传播 | 与「固定训练」诉求相反 | 不做 |

A + C 的组合最自然：**设置 → 开赛时解析为 `AccentPolicy` → 会话内不变**。这与 `AudioTrainingProfile` 的「每局一份不可变配置」模式一致。

## 4. 详细设计

### 4.1 枚举与策略

新增 `lib/audio/accent_policy.dart`（**不要**放进 `app_settings.dart`，避免 `AudioLoader ↔ AppSettings` 的循环 import）：

```dart
enum IncomingAccent {
  auto('auto', 'Auto', null),
  us('us', 'US', 'US'),
  uk('uk', 'UK', 'UK'),
  jp('jp', 'Japan', 'JP'),
  ru('ru', 'Russia', 'RU'),
  india('in', 'India / SEA', 'IN');

  const IncomingAccent(this.id, this.label, this.assetDir);
  final String id;
  final String label;
  final String? assetDir;

  static IncomingAccent fromId(String? id) =>
      values.firstWhere((it) => it.id == id, orElse: () => auto);
}

class AccentPolicy {
  const AccentPolicy(this.accent);
  final IncomingAccent accent;

  /// 本台始终使用 Global；来台按设置为固定口音，否则沿用 DXCC 映射。
  String resolve({required bool isMe, required int dxccId}) {
    if (isMe) return myAudioAccentDir;
    final fixed = accent.assetDir;
    return fixed ?? obtainAccentByDxccId(dxccId);
  }
}
```

`obtainAccentByDxccId` 保持为纯函数（Auto 分支的行为不变），便于现有测试继续覆盖。

### 4.2 设置持久化

`AppSettings` 增加：

```dart
IncomingAccent get incomingAccent =>
    IncomingAccent.fromId(_prefs.getString(_settingIncomingAccent));

set incomingAccent(IncomingAccent value) =>
    _prefs.setString(_settingIncomingAccent, value.id);
```

- key：`setting_incoming_accent`，值用字符串 id（比索引稳定，未来可插入新口音）。
- 旧版本无该 key → `auto`，行为不变。

### 4.3 注入与调用替换

在 `ContestManager.startContest` 时用 `AccentPolicy(_settings.incomingAccent)` 构造会话级策略，传给 `ContestStateChangeHandler` / `ContestOperationEventHandler`：

```dart
// before
await _audioLoader.loadAudio(obtainAssetDir(false, dxccId), payload);

// after
await _audioLoader.loadAudio(
  _accentPolicy.resolve(isMe: false, dxccId: dxccId),
  payload,
);
```

替换范围（只列来台路径）：

| 文件 | 处理 |
|---|---|
| `lib/audio/payload_to_audio.dart` | 删除 `obtainAssetDir`，或改为 `@Deprecated` 仅内部使用 |
| `lib/contest_run/new/contest_state_change_handler.dart` | 所有 `obtainAccentByDxccId(...)` / `obtainAssetDir(false, ...)` → `_accentPolicy.resolve(...)` |
| `lib/contest_run/new/contest_operation_event_handler.dart` | 仅 `myAudioAccentDir`，**不改** |
| 其他 | 搜索确认无遗漏 |

> 不建议把 `AppSettings` 传进 `AudioLoader`：音频层应只接收「资源目录字符串」，保持可单测（现有 `AudioLoader` 已通过 `accentDir` 参数做到了这一点）。

### 4.4 设置界面

在 `lib/ui/main_settings/options_setting.dart` 的 `PhonicType` 下拉之后增加：

```
Incoming accent   [Auto / US / UK / Japan / Russia / India / SEA]
                  helper: "Auto follows each station's DXCC entity."
```

- 复用 `_menu<T>` 组件与 `enabled`（运行中禁用）逻辑。
- `Semantics(label: 'Incoming station accent', value: state.accent.label)`，与现有无障碍风格一致。
- 文案用英文（现有设置页全英文），中文文档不要求改 UI 语言。

### 4.5 成绩元数据

`TrainingRunMetadata` 增加字段：

```dart
class TrainingRunMetadata {
  const TrainingRunMetadata({
    // ...现有字段
    this.accentId = 'auto', // 默认值，避免改动所有构造点
  });

  final String accentId; // 'auto' | 'us' | ...
}
```

- `toJson` 在 `TrainingRunReview` 中输出 `accentId`；
- `decode` 缺省 `'auto'`，兼容 0.2.x 的历史记录；
- 回放/复盘页可显示「Accent: US」；
- 上传排行榜时附带该字段（服务端仅记录，不拆榜）。

### 4.6 与语音包分发的交互

固定口音把「用户可选口音」变成「必须能提供对应资源」。**v0.3.0 已确认不做语音压缩与按口音拆包**，因此直接采用全量随包：5 种口音 + `Global` 均可用，选择任意口音都不需要下载、也不会触发回退。

以下策略仅作为未来拆包时的备忘录：

| 策略 | 随包内容 | 选择未随包口音时 | 备注 |
|---|---|---|---|
| **S1 全量（v0.3.0 采用）** | Global + 5 种口音 | 直接可用 | 资源完整，无网络依赖 |
| S2 随包 Global + US，其余按需下载 | Global + US | 提示下载 | 安装包更小，但需下载通道 |
| S3 随包 Global + US，不提供下载 | Global + US | 选项置灰 | 「固定 UK」不可用 |

- 若未来改为 S2/S3，`Global` **必须随包**：它既是本台音色，也是兜底资源。
- 届时回退行为必须确定：**「先提示、再回退」**，而不是静默变调；否则用户以为在练 UK，实际听的是 Global。

### 4.7 边界情况

| 场景 | 行为 |
|---|---|
| DXCC 查找失败（未知呼号） | Auto 下沿用现有 `US` 兜底；固定口音时直接用固定值 |
| `RU/Common` 缺 1 个文件 | 现有兜底到 `Global/Common`，无需特殊处理 |
| 运行中切换设置 | 设置控件禁用；会话内 `AccentPolicy` 不可变 |
| 旧成绩记录无 `accentId` | 解码为 `auto`，不报错 |
| 练习种子回放 | 题目不变；口音按**当前设置**播放（因为旧记录可能没有 accentId）；若记录中有值，可提示「本局原为 US」 |
| 固定口音 + `PhonicType.mixed` | 正常：口音固定、拼读法仍由种子随机 |

### 5.1 测试用例

1. **Auto 回归**：对现有全部 DXCC 测试集，`AccentPolicy(auto).resolve(false, id)` 与 `obtainAccentByDxccId(id)` 完全一致。
2. **固定口音**：`AccentPolicy(us/uk/jp/ru/in).resolve(false, anyId)` 返回对应目录；`resolve(isMe: true, ...)` 始终 `Global`。
3. **持久化**：写入 `uk` → 重建 `AppSettings` → 仍为 `uk`；无 key → `auto`。
4. **元数据兼容**：0.2.x 的 review JSON 解码后 `accentId == 'auto'`；新记录往返不丢字段。
5. **UI**：下拉选择后写入设置；运行中禁用；语义标签存在。
6. **资源降级**：RU 缺失 Common 片段时仍返回 Global 音频（现有 `audio_loader` 兜底测试扩展）。

### 5.2 验收标准

- 默认安装、不改设置时，任意一局的音频与 v0.2.0 **逐字节一致**（可用同一 questionSeed + audioSeed 对拍 PCM）。
- 选择 `US` 后，来台音频不再出现 JP/RU/UK/IN 目录的片段（可用日志/测试断言资源路径前缀）。
- 选择口音后重启应用仍生效。
- 复盘与上传数据中能看到 `accentId`。

## 6. 风险与待确认

| 风险 | 说明 | 缓解 |
|---|---|---|
| 真实感下降 | 全世界都是同一种口音，训练迁移性变差 | 保留 `Auto` 为默认；UI 说明「固定口音用于专项练习」 |
| 公平性 | 固定口音让成绩更稳定，可能略「容易」 | 上传时记录 `accentId`；观察后再决定是否拆榜 |
| 未来拆包 | 若后续按口音拆包，选了未安装口音可能静默回退 | 先提示、再回退，并提供下载入口；见 §4.6 |
| 设置项过多 | 设置页已有模式/时长/难度/拼读/音量/按键/种子/历史 | 放在「Phonic type」同组，避免新增分组 |
| 循环依赖 | `audio_loader` 与 `app_settings` 互相 import | 枚举/策略独立文件，音频层只接收字符串 |
| 未来口音扩展 | 增加澳/新西兰等口音 | `IncomingAccent` 用字符串 id 持久化，便于扩展 |

### 已确认决策（2026-10-28）

| 编号 | 议题 | 决策 | 落地要点 |
|---|---|---|---|
| D1 | 固定口音是否影响「本台」发音 | **否** | 本台 `myAudioAccentDir` 调用保持不变；`AccentPolicy.resolve(isMe: true)` 恒返回 `Global`，测试需断言其不随设置变化 |
| D2 | 排行榜是否按口音过滤/拆榜 | **先记录，不拆** | 上传成绩仅附带 `accentId`，榜单不分区；待观察固定口音用户的成绩分布后再评估是否拆榜 |
| D3 | 设置文案是否中英双语 | **仅英文** | 与现有设置页保持一致，不引入双语；本文档的中文描述不要求同步改动 UI 文案 |
