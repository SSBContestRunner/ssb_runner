# SSB Runner 0.2.1-alpha02 Release Notes

Version: `0.2.1+201002`

This release fixes three problems reported against `0.2.1-alpha01`: **the same
station appearing in two consecutive questions**, **a round going silent when
the callsign was mis-copied**, and **the state machine freezing when a QSO could
not be logged**. It also adds handling for duplicate QSOs. **It introduces no
breaking changes, and there is no database schema or event-log format change.**

## Question Generation and Replay

- **Consecutive questions never reuse a station.** Callsigns are now drawn
  **without replacement**: each station is a target at most once per run, and
  the pile-up contenders come from the same remaining pool. When the pool runs
  out the run ends normally and the review says every available station has
  been used.
- **Replay no longer restarts at question one.** Previously the recorded
  answers ran out and the fallback regenerated from the same seed, so question
  N+1 was identical to question 1 — which looked like "the station I just
  worked is back". The recording now **ends the replay when exhausted**, and the
  review reports that all recorded answers have been replayed.
- **Start and answer logging was added.** The log records the answer source
  (live / recorded replay / seed replay), the question index, callsign,
  exchange and pile-up list, so this class of bug can be identified from the
  log alone.

## Silence After a Mis-copied Callsign

- **A wrong copy no longer mutes the round.** A mismatched or invalid
  submission used to overwrite the round's audio with "no playback", and
  `Retry` copied it verbatim, so F1 (CQ), F7 (AGN) and the 10 s timeout retries
  were all silent — the operator had to guess the callsign from memory. A
  mis-copied submission now **replays the whole pile-up (or the target
  callsign)**, and retries and timeouts play normally.
- **Invalid callsigns return to a listening state.** `CallsignInvalid` no
  longer lands in a silent state but returns to `WaitingSubmitCall`, which
  replays the answer.
- **The repeat state keeps its pile-up.** When the copy differs too much and
  he repeats the correct call, the pile-up list is carried along and is no
  longer lost on a failed re-submit.

## QSO Logging and State Progress

- **A failed insert no longer freezes the run.** `QsoEnd` / `SpQsoEnd` only
  handle `NextCall` and arm no retry timer, so an empty copy, a null insert or
  a scoring error used to return early and park the machine in the sign-off
  state forever. **Committing is best effort, advancing is unconditional**: an
  error is logged and the next question starts anyway.
- **Run mode commits from the state snapshot.** The sign-off audio loads
  asynchronously and the operator can clear the fields meanwhile; the QSO is
  now logged from the state snapshot instead of the live input.
- **S&P now validates the callsign.** The second Enter only checked the
  exchange, so clearing the call field after pouncing entered `SpQsoEnd`,
  which accepts nothing but `NextCall`. The state is now refused without his
  call.
- **Exhausted answer sources end cleanly.** Running out of answers, a scoring
  error or a failed insert no longer leaves an uncaught asynchronous error;
  stopping a run cancels its retry timer and drops late callbacks.

## Duplicate QSOs

- A station (after callsign normalisation) counts once per run: **the first
  record scores, later duplicates stay in the result table marked `DUPE`** and
  add no points, contacts, multipliers or penalties.
- The review shows a `Duplicates` stat only when duplicates actually occurred.

## Tests

- Added `test/contest_state_change_handler_test.dart` covering the full copy,
  corrected call, input cleared during sign-off, and failing-insert paths.
- Expanded the single-call state machine, replay, scoring, contest definition
  and result table tests to cover retry audio after a wrong copy, exhausted
  answer sources and duplicate scoring.

## Platforms and Installation

Only desktop platforms are packaged for release: Windows x64, macOS universal
(Apple Silicon and Intel), and Linux x86_64 (glibc 2.35+).

The installers are **unsigned**:

- **Windows** may warn about an unknown publisher — choose *More info → Run
  anyway*.
- **macOS** — right-click the app and choose *Open*, or allow it under
  *System Settings → Privacy & Security*.
