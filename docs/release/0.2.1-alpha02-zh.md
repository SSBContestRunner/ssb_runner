# SSB Runner 0.2.1-alpha02 更新说明

版本：`0.2.1+201002`

本版本修复了 `0.2.1-alpha01` 反馈的三类问题：**相邻两题出到同一个台**、**抄错呼号后整题静音卡死**、**QSO 无法落库时状态机硬冻结**，并新增重复 QSO 的识别与处置。**本版本不引入破坏性变更，也没有数据库结构或事件日志格式变更。**

## 出题与重放

- **相邻两题不会再是同一个台。** 呼号改为**无放回抽取**：同一局内每个呼号只会作为目标出现一次，pileup 里的陪衬台也不会重复；呼号池耗尽时本局正常结束，复盘显示「所有可用电台已练完」。
- **重放不再从第 1 题重新开始。** 之前重放的答案记录用完后，会用同一随机种子重新出题，于是第 N+1 题与第 1 题完全相同（表现为「刚通联过的台又出现了」）。现在**记录用完即结束重放**，复盘显示「重放完成，所有记录题目已重放」，不会再倒退题目流。
- **新增开局与出题日志。** 记录本局来源（实时 / 录制重放 / 种子重放）、答案序号、呼号、序号与 pileup 列表，同类问题可直接从日志定位。

## 抄错呼号后的静音卡死

- **抄错不再让整题失声。** 之前提交不匹配或非法的呼号会把本轮的播放类型永久改成「不播放」，F1（CQ）、F7（AGN）与 10 秒自动重试全部静音，只能靠记忆猜对才能继续。现在抄错时**重新播放整段 pileup（或目标台呼号）**，重试与超时都会正常出声。
- **非法呼号回到可重听状态。** `CallsignInvalid` 不再落到静音状态，而是回到等待提交、可重放呼号的 `WaitingSubmitCall`。
- **重发状态保留 pileup。** 呼号差异过大进入重发状态时会带回 pileup 列表，再次抄错也不会丢失陪衬台。

## QSO 落库与状态机推进

- **落库失败不再冻结本局。** `QsoEnd` / `SpQsoEnd` 只处理 `NextCall` 且不挂重试定时器，此前输入为空、插入返回 null 或计分异常都会提前返回，把状态机永久停在结束状态。现在**提交尽力而为、推进无条件执行**：异常只记录日志，本局照常进入下一题。
- **Run 模式改用状态快照落库。** 结束状态的语音加载是异步的，操作员可能在此期间清空输入框；现在从状态快照读取提交内容，不再依赖实时输入。
- **S&P 模式补上呼号校验。** 第二次回车只校验序号，扑上去后清空呼号框会进入只接受 `NextCall` 的 `SpQsoEnd`，从而卡死；现在呼号为空时不会进入该状态。
- **重放与出题异常可安全结束。** 答案源耗尽、判定或计分异常时不会留下未捕获的异步错误；退出训练时会取消重试定时器并丢弃迟到的回调。

## 重复 QSO

- 同一局内同一呼号（归一化后）只计一次：**首条记录计分，之后的重复记录保留在结果表中但标记 `DUPE`**，不计分数、QSO 数、乘数与罚分。
- 复盘新增 `Duplicates` 统计，只在实际存在重复时显示。

## 测试

- 新增 `test/contest_state_change_handler_test.dart`：覆盖完整抄收、更正呼号、结束期间清空输入、插入失败四条路径。
- 扩充单呼状态机、重放、计分、赛制定义与结果表测试，覆盖抄错后重试音频、答案源耗尽与重复计分。
