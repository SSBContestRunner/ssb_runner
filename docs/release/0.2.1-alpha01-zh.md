# SSB Runner 0.2.1-alpha01 更新说明

版本：`0.2.1+201001`

本版本修复 `0.2.0` 中暴露的问题：Windows 上「文档」目录被重定向导致的启动崩溃、关闭窗口后进程残留，以及首次启动过慢。**本版本不引入破坏性变更。**

> 如果你是从 `0.1.0-alpha` 或更早版本升级，请先阅读 [0.2.0 更新说明](https://github.com/SSBContestRunner/ssb_runner/releases/tag/v0.2.0) 的「重要变更」一节：应用标识变更会导致偏好设置重置。

## 启动与存储修复

- **修复 Windows 上「文档」目录被重定向时的启动崩溃。** 被重定向的「文档」目录（例如被 OneDrive 接管）可能显示为存在，但其下的任何写入都以 `ERROR_PATH_NOT_FOUND` 失败。drift 会隐式创建数据库目录，于是这个错误直接表现为启动崩溃。现在**数据库不再放在「文档」目录**，而是与日志同放在应用数据目录下，并把路径显式传给 drift。

  | 平台 | 数据库路径 |
  | --- | --- |
  | Windows | `%APPDATA%\com.ssbrunner\ssb_runner\db` |
  | macOS | `~/Library/Application Support/com.ssbrunner.app/db` |
  | Linux | `~/.local/share/com.ssbrunner.app/db` |

- **既有历史记录会自动迁移。** 首次启动会把旧版本写在「文档」目录下的数据库（`文档/ssb_runner/db`）复制到新位置，**QSO 历史会保留**；旧文件保持原样，不会删除。
- **存储异常不再阻塞启动。** 使用前会先探测目录可写性；首选位置不可用时依次退回临时目录、程序所在目录，并在界面上说明历史记录的实际存放位置。迁移失败也只会在启动后提示，不影响使用。
- **DXCC 缓存读写失败不再导致应用退出。** 前缀加载或缓存读写失败现在只记录日志并继续运行。
- **启动日志新增存储探测信息**，记录各存储根目录的类型与符号链接状态，便于在导出的诊断信息中定位「文档」重定向问题。

## 启动性能优化

- **DXCC 前缀表改为构建期生成。** 首次启动不再解析 cty XML 并逐条插入 4826 行，前缀在单个事务中写入，呼号查询改为 `Map` 查找。macOS release 构建实测 `dxcc_loaded` 从 **3842 ms 降到 32 ms**（后续启动 15 ms），`application ready` 为 **125 ms**。
- **音频初始化与其余启动步骤并行。** SoLoud 与其他步骤同时启动，仅在应用就绪前等待，其 80–165 ms 不再位于关键路径上。
- **启动时不再出现空白窗口。** 窗口在首帧绘制前保持透明，首帧后直接显示加载界面（macOS 与 Linux）。

## 退出修复

- **关闭窗口后进程一定会结束。** Windows 上引擎在消息循环退出之前被同步析构，一旦析构被阻塞，窗口虽已消失，进程却会以空闲状态残留在任务管理器。现在每个清理步骤都有超时上限，SoLoud 的释放通过 `deinitAsync` 移出 UI isolate，并保留 5 秒兜底强制结束进程。

## CI

- 新增「关闭窗口后进程退出」冒烟测试：Windows `WM_CLOSE`（空闲、注入卡死、启动中关闭三种场景）、macOS（基于 dmg）、Debian（Xvfb 下）。
- macOS 冒烟测试改为把 `.app` 复制到明确的路径，确保能找到应用包。

## 平台与安装

仅打包桌面平台：Windows x64、macOS universal（Apple Silicon 与 Intel）、Linux x86_64（glibc 2.35+）。

安装包**未签名**：

- **Windows** 可能提示未知发布者 — 选择 *更多信息 → 仍要运行*。
- **macOS** — 右键点击应用并选择 *打开*，或在 *系统设置 → 隐私与安全性* 中允许。
