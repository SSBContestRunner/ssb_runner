# SSB Runner 0.2.1 Release Notes

Version: `0.2.1+201003`

This release fixes the problems found in `0.2.0`: **a fatal startup crash on
Windows when Documents is redirected**, **a process that stayed alive after the
window was closed**, and **a slow first launch**. It also fixes three problems
reported against the `0.2.1` preview builds: **the same station appearing in
two consecutive questions**, **a round going silent when the callsign was
mis-copied**, and **the state machine freezing when a QSO could not be logged**,
and adds handling for duplicate QSOs. **It introduces no breaking changes, and
there is no database schema or event-log format change.**

> If you are upgrading from `0.1.0-alpha` or earlier, read "Important Changes"
> in the [0.2.0 release notes](https://github.com/SSBContestRunner/ssb_runner/releases/tag/v0.2.0)
> first: the application identifier change resets preferences.

## Startup and Storage Fixes

- **Fixed the Windows startup crash when Documents is redirected.** A redirected
  Documents folder (for example by OneDrive) can report as existing while every
  write below it fails with `ERROR_PATH_NOT_FOUND`. drift created its folder
  implicitly, so the failure surfaced as a fatal crash at startup. The app now
  **keeps the database out of Documents**, next to the logs in the application
  data directory, and passes the path to drift explicitly.

  | Platform | Database path |
  | --- | --- |
  | Windows | `%APPDATA%\com.ssbrunner\ssb_runner\db` |
  | macOS | `~/Library/Application Support/com.ssbrunner.app/db` |
  | Linux | `~/.local/share/com.ssbrunner.app/db` |

- **Existing history is migrated automatically.** On first launch the database
  written by older versions (`Documents/ssb_runner/db`) is copied into the new
  location, so your QSO history carries over. The old files are left untouched.
- **Startup never blocks on storage problems.** The directory is probed for
  writability before it is used; if the preferred location is unavailable the
  app falls back to the temporary directory and then to the folder holding the
  executable, and tells you where the history is actually stored. A failed
  migration only shows a warning after startup.
- **DXCC cache failures no longer take the app down.** A failed prefix load or
  cache read/write now logs and continues instead of aborting startup.
- **A storage probe is recorded in the boot log**, including the type and
  symlink state of each storage root, so a broken Documents redirect is visible
  in the exported diagnostics.

## Faster Startup

- **The DXCC prefix table is generated at build time.** First launch no longer
  parses the cty XML and inserts 4826 rows one statement at a time; the prefixes
  are seeded in a single transaction and callsign lookups are answered from a
  `Map`. Measured on a macOS release build, `dxcc_loaded` dropped from **3842 ms
  to 32 ms** cold (15 ms warm), with the app ready at **125 ms**.
- **Audio initialization runs alongside the rest of the boot sequence.** SoLoud
  is started in parallel and awaited only before the app becomes ready, removing
  its 80–165 ms from the critical path.
- **No more blank window at launch.** The window stays transparent until the
  first frame is painted and is revealed straight into the loading view
  (macOS and Linux).

## Exit Fix

- **The process always ends when the window closes.** On Windows the engine is
  destroyed synchronously before the message loop quits, so a blocked teardown
  left the window gone but the process idle in Task Manager. Cleanup steps are
  now bounded, the SoLoud teardown runs off the UI isolate via `deinitAsync`,
  and a 5 s hard fallback terminates the process if cleanup still hangs.

## Question Generation and Replay

- **Consecutive questions never reuse a station.** Callsigns are drawn
  **without replacement**: each station is a target at most once per run, and
  the pile-up contenders come from the same remaining pool. When the pool runs
  out the run ends normally and the review says every available station has
  been used.
- **Replay no longer restarts at question one.** Previously the recorded
  answers ran out and the fallback regenerated from the same seed, so question
  N+1 was identical to question 1 — which looked like "the station I just
  worked is back". The recording now **ends the replay when exhausted**, and the
  review reports that all recorded answers have been replayed.
- **Start and answer logging was added.** The log records the answer source
  (live / recorded replay / seed replay), the question index, callsign,
  exchange and pile-up list, so this class of bug can be identified from the
  log alone.

## Silence After a Mis-copied Callsign

- **A wrong copy no longer mutes the round.** A mismatched or invalid
  submission used to overwrite the round's audio with "no playback", and
  `Retry` copied it verbatim, so F1 (CQ), F7 (AGN) and the 10 s timeout retries
  were all silent — the operator had to guess the callsign from memory. A
  mis-copied submission now **replays the whole pile-up (or the target
  callsign)**, and retries and timeouts play normally.
- **Invalid callsigns return to a listening state.** `CallsignInvalid` no
  longer lands in a silent state but returns to `WaitingSubmitCall`, which
  replays the answer.
- **The repeat state keeps its pile-up.** When the copy differs too much and
  he repeats the correct call, the pile-up list is carried along and is no
  longer lost on a failed re-submit.

## QSO Logging and State Progress

- **A failed insert no longer freezes the run.** `QsoEnd` / `SpQsoEnd` only
  handle `NextCall` and arm no retry timer, so an empty copy, a null insert or
  a scoring error used to return early and park the machine in the sign-off
  state forever. **Committing is best effort, advancing is unconditional**: an
  error is logged and the next question starts anyway.
- **Run mode commits from the state snapshot.** The sign-off audio loads
  asynchronously and the operator can clear the fields meanwhile; the QSO is
  now logged from the state snapshot instead of the live input.
- **S&P now validates the callsign.** The second Enter only checked the
  exchange, so clearing the call field after pouncing entered `SpQsoEnd`,
  which accepts nothing but `NextCall`. The state is now refused without his
  call.
- **Exhausted answer sources end cleanly.** Running out of answers, a scoring
  error or a failed insert no longer leaves an uncaught asynchronous error;
  stopping a run cancels its retry timer and drops late callbacks.

## Duplicate QSOs

- A station (after callsign normalisation) counts once per run: **the first
  record scores, later duplicates stay in the result table marked `DUPE`** and
  add no points, contacts, multipliers or penalties.
- The review shows a `Duplicates` stat only when duplicates actually occurred.

## Tests

- Added `test/contest_state_change_handler_test.dart` covering the full copy,
  corrected call, input cleared during sign-off, and failing-insert paths.
- Expanded the single-call state machine, replay, scoring, contest definition
  and result table tests to cover retry audio after a wrong copy, exhausted
  answer sources and duplicate scoring.
- Added bounded-exit-cleanup tests and window-close smoke tests on Windows,
  macOS and Debian: each asserts the process is gone after the window closes.

## Platforms and Installation

Only desktop platforms are packaged for release: Windows x64, macOS universal
(Apple Silicon and Intel), and Linux x86_64 (glibc 2.35+).

The installers are **unsigned**:

- **Windows** may warn about an unknown publisher — choose *More info → Run
  anyway*.
- **macOS** — right-click the app and choose *Open*, or allow it under
  *System Settings → Privacy & Security*.
