# SSB Runner 0.2.1 更新说明

版本：`0.2.1+201003`

本版本修复了 `0.2.0` 中暴露的问题：**Windows 上「文档」目录被重定向导致的启动崩溃**、**关闭窗口后进程残留**，以及**首次启动过慢**。同时修复了 `0.2.1` 预览版反馈的三类问题：**相邻两题出到同一个台**、**抄错呼号后整题静音卡死**、**QSO 无法落库时状态机硬冻结**，并新增重复 QSO 的识别与处置。**本版本不引入破坏性变更，也没有数据库结构或事件日志格式变更。**

> 如果你是从 `0.1.0-alpha` 或更早版本升级，请先阅读 [0.2.0 更新说明](https://github.com/SSBContestRunner/ssb_runner/releases/tag/v0.2.0) 的「重要变更」一节：应用标识变更会导致偏好设置重置。

## 启动与存储修复

- **修复 Windows 上「文档」目录被重定向时的启动崩溃。** 被重定向的「文档」目录（例如被 OneDrive 接管）可能显示为存在，但其下的任何写入都以 `ERROR_PATH_NOT_FOUND` 失败。drift 会隐式创建数据库目录，于是这个错误直接表现为启动崩溃。现在**数据库不再放在「文档」目录**，而是与日志同放在应用数据目录下，并把路径显式传给 drift。

  | 平台 | 数据库路径 |
  | --- | --- |
  | Windows | `%APPDATA%\com.ssbrunner\ssb_runner\db` |
  | macOS | `~/Library/Application Support/com.ssbrunner.app/db` |
  | Linux | `~/.local/share/com.ssbrunner.app/db` |

- **既有历史记录会自动迁移。** 首次启动会把旧版本写在「文档」目录下的数据库（`文档/ssb_runner/db`）复制到新位置，**QSO 历史会保留**；旧文件保持原样，不会删除。
- **存储异常不再阻塞启动。** 使用前会先探测目录可写性；首选位置不可用时依次退回临时目录、程序所在目录，并在界面上说明历史记录的实际存放位置。迁移失败也只会在启动后提示，不影响使用。
- **DXCC 缓存读写失败不再导致应用退出。** 前缀加载或缓存读写失败现在只记录日志并继续运行。
- **启动日志新增存储探测信息**，记录各存储根目录的类型与符号链接状态，便于在导出的诊断信息中定位「文档」重定向问题。

## 启动性能优化

- **DXCC 前缀表改为构建期生成。** 首次启动不再解析 cty XML 并逐条插入 4826 行，前缀在单个事务中写入，呼号查询改为 `Map` 查找。macOS release 构建实测 `dxcc_loaded` 从 **3842 ms 降到 32 ms**（后续启动 15 ms），`application ready` 为 **125 ms**。
- **音频初始化与其余启动步骤并行。** SoLoud 与其他步骤同时启动，仅在应用就绪前等待，其 80–165 ms 不再位于关键路径上。
- **启动时不再出现空白窗口。** 窗口在首帧绘制前保持透明，首帧后直接显示加载界面（macOS 与 Linux）。

## 退出修复

- **关闭窗口后进程一定会结束。** Windows 上引擎在消息循环退出之前被同步析构，一旦析构被阻塞，窗口虽已消失，进程却会以空闲状态残留在任务管理器。现在每个清理步骤都有超时上限，SoLoud 的释放通过 `deinitAsync` 移出 UI isolate，并保留 5 秒兜底强制结束进程。

## 出题与重放

- **相邻两题不会再是同一个台。** 呼号改为**无放回抽取**：同一局内每个呼号只会作为目标出现一次，pileup 里的陪衬台也不会重复；呼号池耗尽时本局正常结束，复盘显示「所有可用电台已练完」。
- **重放不再从第 1 题重新开始。** 之前重放的答案记录用完后，会用同一随机种子重新出题，于是第 N+1 题与第 1 题完全相同（表现为「刚通联过的台又出现了」）。现在**记录用完即结束重放**，复盘显示「重放完成，所有记录题目已重放」，不会再倒退题目流。
- **新增开局与出题日志。** 记录本局来源（实时 / 录制重放 / 种子重放）、答案序号、呼号、序号与 pileup 列表，同类问题可直接从日志定位。

## 抄错呼号后的静音卡死

- **抄错不再让整题失声。** 之前提交不匹配或非法的呼号会把本轮的播放类型永久改成「不播放」，F1（CQ）、F7（AGN）与 10 秒自动重试全部静音，只能靠记忆猜对才能继续。现在抄错时**重新播放整段 pileup（或目标台呼号）**，重试与超时都会正常出声。
- **非法呼号回到可重听状态。** `CallsignInvalid` 不再落到静音状态，而是回到等待提交、可重放呼号的 `WaitingSubmitCall`。
- **重发状态保留 pileup。** 呼号差异过大进入重发状态时会带回 pileup 列表，再次抄错也不会丢失陪衬台。

## QSO 落库与状态机推进

- **落库失败不再冻结本局。** `QsoEnd` / `SpQsoEnd` 只处理 `NextCall` 且不挂重试定时器，此前输入为空、插入返回 null 或计分异常都会提前返回，把状态机永久停在结束状态。现在**提交尽力而为、推进无条件执行**：异常只记录日志，本局照常进入下一题。
- **Run 模式改用状态快照落库。** 结束状态的语音加载是异步的，操作员可能在此期间清空输入框；现在从状态快照读取提交内容，不再依赖实时输入。
- **S&P 模式补上呼号校验。** 第二次回车只校验序号，扑上去后清空呼号框会进入只接受 `NextCall` 的 `SpQsoEnd`，从而卡死；现在呼号为空时不会进入该状态。
- **重放与出题异常可安全结束。** 答案源耗尽、判定或计分异常时不会留下未捕获的异步错误；退出训练时会取消重试定时器并丢弃迟到的回调。

## 重复 QSO

- 同一局内同一呼号（归一化后）只计一次：**首条记录计分，之后的重复记录保留在结果表中但标记 `DUPE`**，不计分数、QSO 数、乘数与罚分。
- 复盘新增 `Duplicates` 统计，只在实际存在重复时显示。

## 测试

- 新增 `test/contest_state_change_handler_test.dart`：覆盖完整抄收、更正呼号、结束期间清空输入、插入失败四条路径。
- 扩充单呼状态机、重放、计分、赛制定义与结果表测试，覆盖抄错后重试音频、答案源耗尽与重复计分。
- 新增退出清理超时上限的单元测试，以及 Windows、macOS、Debian 的「关闭窗口后进程退出」冒烟测试。
