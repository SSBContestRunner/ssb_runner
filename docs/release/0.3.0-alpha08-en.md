# SSB Runner 0.3.0-alpha08 Release Notes

Version: `0.3.0+300008`

**This is still an alpha preview of 0.3.0, not a stable release.** There are no
application changes in this build; the work is in the Windows installer and the
packaging pipeline. An over-install now says which folder it writes to, which
version it replaces and that user data is kept; an older package can no longer
downgrade a newer install; and stale DLLs no longer mix with new ones. The
packaging verification layer is new as well: Inno Setup, dpkg-deb, appimagetool
and appdmg now actually run before merge instead of at tag time. The database
schema and the event-log format are unchanged, so training history and settings
survive the upgrade as is. Use `0.2.1` if you are logging a real contest.

Upgrading from `0.3.0-alpha07` is a plain over-install. Coming from
`0.3.0-alpha06` or earlier, uninstall first: `alpha07` moved the install folder
from `Programs\SSB Runner` to `Programs\SSB_Runner`, so skipping this leaves two
installations behind.

## Windows installer: an over-install now says what it overwrites

- **A new "Upgrade" page appears only when a previous install is detected**,
  placed exactly where Inno silently skips the *Select Destination Location*
  page. It shows the installed version → this package's version, the real target
  folder, and a note that settings and training records live in the user data
  folder and are kept.
- **The folder shown is the real one, not the configured default.** The page
  reads the wizard's effective directory, so when the old install sits elsewhere
  (for example `alpha06`'s `Programs\SSB Runner`) it names that folder — the one
  about to be written — instead of the new package's default.
- **Reinstalling the same version says so**, with "this version is already
  installed; Setup will overwrite it", so it no longer looks like a fresh
  install.
- **The silent path is unchanged**: the `/VERYSILENT` flow used by in-app update
  shows no extra page and no extra dialog.
- **Detection** reads `DisplayVersion` from the per-user uninstall entry, falls
  back to `Inno Setup: App Path` / `InstallLocation` for the folder, and still
  treats "folder exists, version missing" as an over-install.

## Downgrades are refused

- **An older package can no longer silently overwrite a newer install.** When
  the installed version is higher than the package, Setup aborts before the
  wizard exists: interactively it shows one "Cannot continue" error naming both
  versions, and in silent mode it only writes the log and exits non-zero. Neither
  path modifies the install folder.
- **There is no "continue anyway".** Database migrations only go forward
  (schema v7 today), so an older build reading a newer database is undefined.

## No more stale files after an over-install

- **Files this build always rewrites are removed first**: `{app}\*.dll` and
  `{app}\data` are deleted before the new files are written, so DLLs and
  resources dropped by an older version cannot linger next to new ones.
- **`db\` and `log\` are explicitly excluded.** The app's data root can fall
  back to the exe folder in extreme cases, where it would hold real training
  records and logs, so the installer never touches them.
- **Overwrite behaviour no longer depends on Inno's version defaults**:
  `CloseApplications=yes` (Restart Manager closes processes that hold files
  about to be replaced, so a failed write cannot still report success) and
  `RestartApplications=no` (the in-app update restarts the app; Setup does not
  launch a second copy).

## Packaging and CI: the packaging scripts now really run before merge

- **A static packaging contract (L0) was added** for all three platforms'
  `make_config.yaml`, templates, CI orchestration and packager pin, with
  `flutter test` fixtures covering the checker itself.
- **A three-platform packaging dry run was added**: the real
  `flutter_app_packager` API runs against a stub bundle, so ISCC, dpkg-deb,
  appimagetool and appdmg execute for real. Previously nothing compiled the
  installer script until a tag was pushed — one folded `[` was enough to break a
  package build.
- **Dry runs and real packaging are mutually exclusive**: the validation jobs
  run on pull requests and the merge queue only, so the same maker chain never
  runs twice for one event.
- **The Linux and macOS native runners now compile on every PR**, matching
  Windows, and all three compile jobs are registered with the merge queue.
- **Only transient packaging failures are retried**: a real compiler diagnostic
  (`error C####`) fails immediately, and a failed Windows package uploads the
  rendered `.iss` for inspection.
- **The installer smoke test grew**: it installs the same package twice (the
  second pass exercises the same-version path) and rewrites the uninstall
  entry's version to `99.0.0` to prove the downgrade block leaves the install
  untouched.

## Known Limitations (Alpha)

- **Preview only.** Treat 0.3.0-alpha08 as a test build; use `0.2.1` for real
  contest logging.
- **Supported systems**: Windows 10 version 1607 (build 14393) or later, macOS
  13 Ventura or later, Linux with glibc 2.35 or later. Windows 10 1507/1511,
  macOS 12 and older distros are not supported; on 1607 the process is
  DPI-unaware, so at 125 %/150 % the UI is bitmap-stretched (per-monitor scaling
  starts with 1703).
- **Audio warnings depend on the platform probe.** If the system exposes
  neither volume, mute nor a default device, the badge stays silent by design.
  Linux support requires `pactl` (PulseAudio/PipeWire) or `wpctl`; macOS uses the
  default output device only.
- **No downgrade, and the installer now enforces it.** The database is migrated
  to schema v7. A `0.2.x` build may refuse to open a database written by this
  alpha, and QSOs logged here should be exported/backed up before switching
  back; an older package is refused outright by Setup.
- **Old recordings cannot prove ownership.** Session replay requires the
  run-start header added in 0.3.0. A pending replay armed from a `0.2.1` or
  earlier recording is refused and the run starts from the current settings.
- **No online leaderboard.** Score submission and the server-side replay
  verification described in the design notes are not part of this alpha.
- **Installers are unsigned** (see below).

## Platforms and Installation

Only desktop platforms are packaged for release: Windows x64, macOS universal
(Apple Silicon and Intel), and Linux x86_64.

- **Windows** — `*windows-setup.exe` (per user, no elevation; refuses Windows
  older than 10 1607) or `*windows.zip`. On 1607 the process is DPI-unaware, so
  at 125 %/150 % the UI is bitmap-stretched; per-monitor scaling starts with
  Windows 10 1703.
- **macOS** — `*macos.dmg`, drag **SSB Runner.app** into *Applications*.
  Requires macOS 13 Ventura or later; Intel support is best-effort.
- **Linux** — `.deb`, `.AppImage` and `.zip`; all three require glibc 2.35+.
  The AppImage needs FUSE 2 to mount, or run it with
  `--appimage-extract-and-run`.

The installers are **unsigned**:

- **Windows** may warn about an unknown publisher — choose *More info → Run
  anyway*.
- **macOS** — right-click the app and choose *Open*, or allow it under
  *System Settings → Privacy & Security*.
