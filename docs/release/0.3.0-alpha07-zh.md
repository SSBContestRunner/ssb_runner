# SSB Runner 0.3.0-alpha07 更新说明

版本：`0.3.0+300007`

**本版本仍是 0.3.0 的 alpha 预览版，不是稳定版。** 本版的重点是音频输出检查：当呼号音频根本听不到时（系统静音、音量过低、没有输出设备、音频引擎未启动），应用会明确提示，而不是让你在一整局静默中练完。此外还修正了真实系统下限（Windows 10 1607、macOS 13、glibc 2.35），修复了 Issue #71 报告的 Windows 10 启动崩溃，补齐了界面用到的中文字形，并打磨了 Windows 安装器。**数据库结构与事件日志格式都没有变化**，升级后训练记录与设置原样保留；如果要记录真实比赛，请继续使用 `0.2.1`。

从 `0.3.0-alpha06` 升级可以直接覆盖安装，但 Windows 有一处例外：安装目录改为 `%LOCALAPPDATA%\Programs\SSB_Runner`（不含空格），请先卸载旧版本，否则两份安装会并存。

## 音频输出监控：听不到呼号时给出提示

- **常驻监控覆盖整条输出链路。** macOS 通过 CoreAudio、Windows 通过 WASAPI、Linux 通过 `pactl` 或 `wpctl` 读取系统音量、静音状态与默认设备，同时轮询 SoLoud 引擎状态。顶栏徽标只在异常时出现，输出正常时完全不占位置。
- **识别四类故障**：系统静音、音量低于 10%、没有输出设备、音频引擎未初始化。音量过低与静音使用不同图标——音量偏小不再被画成「喇叭被划掉」。
- **读不到的值一律视为「未知」，绝不当作健康。** 平台没有对应探针时不报警，避免误报；读取失败时保持当前状态，而不是把已经看到的故障清掉。
- **提示做了防抖。** 静音、无设备、引擎失效属于硬状态，立即显示；进入低音量状态以及**离开**任何告警，需要等 600 ms 静默窗口（系统事件驱动）或连续两个轮询样本（保底定时器），因此拖动音量滑块不会让徽标闪烁。
- **轮询开销很低**：窗口可见时 2 s 一次，隐藏时 10 s 一次（Linux 3 s，因为每次采样都要 fork `pactl`）。采样运行在 `Priority.idle`，事件驱动采样限制为 300 ms 一次，删除了每次采样都调用的 `listPlaybackDevices()` FFI（设备是否存在改由平台默认端点给出），Linux 上音量与静音合并为一次 `pactl` JSON 调用。debug 构建中，单次采样超过 8 ms 会在同一段慢采样中只告警一次，并单独度量平台往返耗时，卡住的 CoreAudio 读取也能被看到。
- 设置 `SSB_RUNNER_DISABLE_AUDIO=1` 可关闭监控，便于排查问题。

## 开始练习：开局预检与会话内提示

- **RUN 前出现预检对话框**，显示故障原因、当前音量与设备名，并提供「重新检查」与跳转系统声音设置的入口。始终可以点「仍然开始」继续；重新检查恢复正常后，对话框会自动关闭并继续开局。
- **只有低音量可以被永久忽略**：在对话框中勾选「不再提示音量过低」，或在设置中关闭同名开关（默认开启）。
- **运行中的会话不会被打断。** 故障以非模态 toast 重复提示，每种原因每局只提示一次，恢复后重新计数；toast 不抢焦点、不暂停计时。
- 开局按钮增加了防重入保护，双击不会再同时开出两局。

## 设置：播放测试音

- **新增「播放测试音」一行**，以录像本身的电平播放一小段样本，方便在开局前把系统音量调到合适位置。样本加载失败时回退到合成音。
- 该行会显示「播放中…」与「音频播放失败」，不再静默失败。

## Windows：10240 不再启动失败

- **现象**。在 Windows 10 RTM（Build 10240，10586 同样受影响）上，窗口出现后应用进入启动失败页，并上报 `ArgumentError`：`Failed to load dynamic library 'cnativeapi.dll'`，`error code: 127`（`The specified procedure could not be found`）。日志里没有任何可解释的信息。
- **原因**。`window_manager` 0.6 通过 nativeapi/cnativeapi 解析窗口，而该 DLL 静态导入了 `user32!GetDpiForWindow`；这个 API 自 Windows 10 1607（Build 14393）才存在，1507/1511 上整个 DLL 无法加载，所有窗口调用都会抛异常。应用侧又把窗口几何当作必需能力，于是「可选能力不可用」被升级成启动致命错误与崩溃上报。
- **修复（便携 zip）**。原生启动流程在 Flutter 引擎启动前检查该 API，并真实加载一次 `cnativeapi.dll`。任一失败就弹出中英双语提示（写明需要 Windows 10 1607 / Build 14393），随后干净退出：不生成崩溃报告、不残留进程、不留半启动的窗口。
- **修复（安装器）**。安装器增加 `MinVersion=10.0.14393`，旧系统会在安装阶段被 Inno Setup 以「不支持当前 Windows 版本」拦下，而不是装上一份无法运行的副本。
- **修复（应用侧）**。窗口解析改为失败即降级：解析不到窗口时返回「无窗口」而不是抛异常，几何恢复与尺寸记忆在没有窗口时跳过，首帧仍会走完正常启动流程。窗口管理不可用时，启动完成后提示一条警告，而不是进入失败页。

## macOS：系统下限是 13 Ventura，不是 12

- **macOS 12 无法运行本构建，现在会明确写出要求。** Flutter 3.47 以固定的 macOS 13 部署目标编译原生资源（sqlite3、cnativeapi、flutter_soloud、objective_c），dyld 在 12 上拒绝加载这些二进制，尽管 Flutter 自身允许。`MACOSX_DEPLOYMENT_TARGET` 与 README 现已改为 bundle 的真实下限，12.x 用户看到的是文档化的系统要求，而不是启动失败。此前「macOS 12 Monterey」的说法是错误的。

## Linux：glibc 2.35 下限现在被真正校验

- **AppImage 曾悄悄内置了更新的 glibc。** 它会把构建机的 `libstdc++` 与 `libgcc_s` 复制进 `usr/lib`，`GLIBC_2.35` 就是这样混进来的：冒烟测试只在 Debian 12 容器里跑，那里一切都解析得通。
- **校验对象改为解包后的 AppImage（含 `usr/lib`）**，按声明中的 2.35 / `GLIBCXX_3.4.30` 下限检查，并像 `.deb` 一样在 Xvfb 下实际启动，验证的是打包后的运行时而不是假设。
- **体积同时变小**：Android 专用的 `libdartjni.so` 拖进来的约 24 MB `libjvm.so` 已从 AppImage 中移除。
- AppImage 仍内置 `libstdc++` 与 `libgcc`，但不含 glibc。挂载需要 FUSE 2，而较新的发行版默认不再安装；没有 FUSE 2 时可用 `--appimage-extract-and-run` 运行。

## Windows 安装器：版式与安装路径

- **向导 Logo 不再贴住窗口边缘。** Inno 会把 `WizardSmallImageFile` 紧贴客户区右上角绘制，而 `[Setup]` 没有边距指令，于是图标紧贴标题栏与右边框。三个 DPI 变体现在都烘焙了统一的 10% 透明内缩；画布尺寸不变，标题与副标题不会移位。
- **默认安装目录改为 `Programs\SSB_Runner`，去掉了空格。** 安装路径中的空格在 Windows 上容易引出引号与工具链问题。显示名称未变，快捷方式仍为「SSB Runner」。产品尚未正式发布，因此不提供迁移——旧 alpha 会留在 `Programs\SSB Runner`，需要手动卸载。

## 字体：界面用到的字形全部内置

- **中文回退字体问题已消除。** 内置的 Noto Sans SC 子集是在暂停与重放文案落地之前生成的，结/束/暂/继/续等字会逐字回退到平台中文字体。Windows 上回退到微软雅黑，而雅黑没有 Medium 字重，于是「结束本局」一行里出现了两种字体、两种字重。
- **子集改为从完整 UI 词表用 `tool/build_fonts.py` 重建**（Noto Sans SC 2.004、Iosevka 34.9.1），并新增 cmap 级覆盖测试：界面文案一旦超出内置字体，测试就会失败。

## 打包与 CI 加固

- **原生 Windows 代码现在在每次 PR 与分支推送时编译。** 此前直到打 tag 都没有门禁，于是一个音频 COM 析构函数上的 `C3668` 直接进了发布流程。该析构函数已改为 `virtual` 声明。
- **`appimagetool` 按 SHA-256 固定版本**；trim 脚本会归一化解包后的 AppDir 权限（build 370 会把 `0700` 目录当作致命错误），并断言重打包后的镜像存在且确实变小，而不是悄悄保留 `libjvm.so`。
- **只重试瞬时打包失败。** 真正的编译器诊断（`error C####`）立即失败，而 `Build process failed.` 仍会重试已知的原生资源瞬时失败。
- **Windows 系统下限纳入 CI 护栏。** 打包任务解析 `Release/` 下所有 `.dll` 与 `.exe` 的导入表；出现高于 Windows 10 1607 的 API 即失败，白名单当前只有 `GetDpiForWindow`、`AdjustWindowRectExForDpi`（均来自 cnativeapi，且已被原生预检覆盖）。后续依赖升级无法再无声抬高真实系统下限。可用 `dart run tool/check_windows_imports.dart <Release 目录>` 复现，该工具可在任意系统运行。

## 已知限制（Alpha）

- **仅供预览。** 请把 0.3.0-alpha07 当作测试版本；真实比赛记录请使用 `0.2.1`。
- **支持的系统**：Windows 10 版本 1607（Build 14393）或更高版本；macOS 13 Ventura 或更高版本；glibc 2.35 或更高的 Linux。不支持 Windows 10 1507/1511、macOS 12 与更旧的发行版；1607 上进程是 DPI 不感知的，125%/150% 缩放下界面会被位图拉伸（PerMonitor 缩放从 1703 开始）。
- **音频提示依赖平台探针。** 若系统既读不到音量、静音也读不到默认设备，徽标按设计保持沉默。Linux 需要 `pactl`（PulseAudio/PipeWire）或 `wpctl`；macOS 只检查默认输出设备。
- **不可降级。** 数据库已迁移到 v7。`0.2.x` 版本可能无法打开本 alpha 写出的数据库，切回旧版前请先导出/备份 QSO 历史。
- **旧录像无法证明归属。** 会话重放依赖 0.3.0 新增的开局记录头。由 `0.2.1` 或更早版本录制的待重放会话会被拒绝，并改为按当前设置开局。
- **没有在线排行榜。** 设计文档中的分数上传与服务端重放校验不在本 alpha 范围内。
- **安装包未签名**（见下文）。

## 平台与安装

仅打包桌面平台：Windows x64、macOS universal（Apple Silicon 与 Intel）、Linux x86_64。

- **Windows** — `*windows-setup.exe`（纯 per-user 安装，不弹 UAC；低于 Windows 10 1607 会拒绝安装）或 `*windows.zip`。1607 上进程 DPI 不感知，125%/150% 缩放下界面会被位图拉伸；PerMonitor 缩放从 Windows 10 1703 开始。
- **macOS** — `*macos.dmg`，把 **SSB Runner.app** 拖入 *Applications*。要求 macOS 13 Ventura 或更高版本；Intel 支持为尽力而为。
- **Linux** — `.deb`、`.AppImage` 与 `.zip`，三者都要求 glibc 2.35+。AppImage 挂载需要 FUSE 2，也可用 `--appimage-extract-and-run` 运行。

安装包**未签名**：

- **Windows** 可能提示未知发布者 — 选择 *更多信息 → 仍要运行*。
- **macOS** — 右键点击应用并选择 *打开*，或在 *系统设置 → 隐私与安全性* 中允许。
