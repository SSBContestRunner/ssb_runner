# SSB Runner 0.2.1-alpha01 Release Notes

Version: `0.2.1+201001`

This release fixes the bugs found in `0.2.0`: a fatal startup crash on Windows
when the Documents folder is redirected, a process that stayed alive after the
window was closed, and a slow first launch. **It introduces no breaking
changes.**

> If you are upgrading from `0.1.0-alpha` or earlier, read "Important Changes"
> in the [0.2.0 release notes](https://github.com/SSBContestRunner/ssb_runner/releases/tag/v0.2.0)
> first: the application identifier change resets preferences.

## Startup and Storage Fixes

- **Fixed the Windows startup crash when Documents is redirected.** A redirected
  Documents folder (for example by OneDrive) can report as existing while every
  write below it fails with `ERROR_PATH_NOT_FOUND`. drift created its folder
  implicitly, so the failure surfaced as a fatal crash at startup. The app now
  **keeps the database out of Documents**, next to the logs in the application
  data directory, and passes the path to drift explicitly.

  | Platform | Database path |
  | --- | --- |
  | Windows | `%APPDATA%\com.ssbrunner\ssb_runner\db` |
  | macOS | `~/Library/Application Support/com.ssbrunner.app/db` |
  | Linux | `~/.local/share/com.ssbrunner.app/db` |

- **Existing history is migrated automatically.** On first launch the database
  written by older versions (`Documents/ssb_runner/db`) is copied into the new
  location, so your QSO history carries over. The old files are left untouched.
- **Startup never blocks on storage problems.** The directory is probed for
  writability before it is used; if the preferred location is unavailable the
  app falls back to the temporary directory and then to the folder holding the
  executable, and tells you where the history is actually stored. A failed
  migration only shows a warning after startup.
- **DXCC cache failures no longer take the app down.** A failed prefix load or
  cache read/write now logs and continues instead of aborting startup.
- **A storage probe is recorded in the boot log**, including the type and
  symlink state of each storage root, so a broken Documents redirect is visible
  in the exported diagnostics.

## Faster Startup

- **The DXCC prefix table is generated at build time.** First launch no longer
  parses the cty XML and inserts 4826 rows one statement at a time; the prefixes
  are seeded in a single transaction and callsign lookups are answered from a
  `Map`. Measured on a macOS release build, `dxcc_loaded` dropped from **3842 ms
  to 32 ms** cold (15 ms warm), with the app ready at **125 ms**.
- **Audio initialization runs alongside the rest of the boot sequence.** SoLoud
  is started in parallel and awaited only before the app becomes ready, removing
  its 80–165 ms from the critical path.
- **No more blank window at launch.** The window stays transparent until the
  first frame is painted and is revealed straight into the loading view
  (macOS and Linux).

## Exit Fix

- **The process always ends when the window closes.** On Windows the engine is
  destroyed synchronously before the message loop quits, so a blocked teardown
  left the window gone but the process idle in Task Manager. Cleanup steps are
  now bounded, the SoLoud teardown runs off the UI isolate via `deinitAsync`,
  and a 5 s hard fallback terminates the process if cleanup still hangs.

## CI

- Added window-close smoke tests that assert the process exits: Windows
  `WM_CLOSE` (idle, injected hang, close during startup), macOS (dmg-based),
  and Debian under Xvfb.
- macOS smoke test copies the `.app` to an explicit path so the bundle is found.

## Platforms and Installation

Only desktop platforms are packaged for release: Windows x64, macOS universal
(Apple Silicon and Intel), and Linux x86_64 (glibc 2.35+).

The installers are **unsigned**:

- **Windows** may warn about an unknown publisher — choose *More info → Run
  anyway*.
- **macOS** — right-click the app and choose *Open*, or allow it under
  *System Settings → Privacy & Security*.
