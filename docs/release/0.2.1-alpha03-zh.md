# SSB Runner 0.2.1-alpha03 更新说明

版本：`0.2.1+201003`

本版本把「抄错呼号」从被拒绝改成**照常完成 QSO 并按抄收原样落库**，并让五个赛制的 log check 口径统一。**本版本不引入数据库结构或事件日志格式变更。**

## 抄错呼号会落库

- **任意非空呼号都会进入 QSO。** 之前呼号与目标差异超过阈值时会被判为无效并退回等待提交，这一题永远无法落库；现在不再拒绝，QSO 正常走到结束并按抄收值记录。
- **序号阶段不再静音。** 抄错的呼号进入序号阶段后会重放对方的**呼号、RST 与序号**；F7 重放包含 AGN 提示，不再出现「抄错一次就整题失声」。
- **本轮目标不会丢失。** 抄错呼号不会清空本轮答案或重新出题，pileup 不会因为一次笔误被换掉。
- **序号阶段提示补充说明。** 五种语言的阶段提示都会注明「抄错的呼号会按原样记录」。

## Log check 与计分

- **呼号错统一判无效并扣 2 倍 QSO 分值。** 五个赛制（CQ WPX、CQ WW、ARRL DX、IARU HF、JIDX）不再有「只判无效、不扣分」的差异；扣分只作用于 Verified 分，Raw 分照常累加，QSO 数不增加。
- **交换信息错保持 NIL。** 官方规则对交换错误的处理是「判无效、不额外扣分」，因此不改为罚分。
- **重复台保持 NIL。** dupe 仍不计分、不计数、不罚分。
- **JIDX 的例外已注明。** JIDX 官方规则没有 log-check 罚分条款，本模拟器为训练口径统一按 2 倍计，`scoringNotice` 中已明确说明这一点。
- **无效前缀与未知 DXCC 不再白送乘数。** 提取不到前缀的呼号不再把空字符串当乘数；DXCC 查询失败（-1）也不再计入 `dxcc--1`。

## 测试

- 状态机：抄错且差异超过阈值时，序号阶段的音频为「呼号 + 序号」。
- 处理链路：偏差超过阈值仍进入序号阶段、错呼号 + 正确序号落库、错呼号 + 错序号落库、本轮目标不被替换、F7 重放四段音频。
- 计分：呼号错使 Verified 下降而 Raw 增长、交换错与 dupe 不改变 Verified、五个赛制的表驱动断言、空前缀与未知 DXCC 的乘数守卫。
