# SSB Runner 0.3.0-alpha02 Release Notes

Version: `0.3.0+300002`

**This is still an alpha preview of 0.3.0, not a stable release.** It fixes the
blank-window/slow-start and window-size problems reported against
`0.3.0-alpha01`, adds a Windows startup timeline diagnostic, and adds SHA-256
verification to the release assets. **There is no database or event-log format
change**; use `0.2.1` if you are logging a real contest.

Upgrading from `0.3.0-alpha01` is a plain over-install: the database, settings
and training history are kept.

## Startup: the first frame no longer waits on disk or platform channels

- **The window appears straight into the loading view.** `main()` no longer
  reads files or awaits `PackageInfo` before the first frame; logging,
  preferences, the database, DXCC prefixes, the callsign tables and audio
  initialisation all start after it, so an empty or white window is no longer
  shown first.
- **Pre-frame logs are not lost.** Records written before the first frame stay
  in an in-memory buffer and are replayed into the log file with their original
  timestamps once the file sink is ready, so the boot trace stays complete.
- **Synchronous file IO on the boot path is now async**, and the executable
  directory listing runs in its own isolate so a virus scanner inspecting each
  file cannot stall the UI.
- **Richer boot diagnostics.** The log now records the first-frame time
  relative to `main()`, how many buffered records were replayed, and the
  window frame/content/minimum sizes with their timing, so any remaining delay
  can be attributed correctly.

## Windows startup timeline diagnostics

- **The whole startup is traceable.** The Windows runner records a native
  timeline of process start → `wWinMain` → Dart `main` → first frame → window
  shown, then folds it together with the Dart boot phases into a single
  `boot timeline` record in `latest.log`; the temporary file is removed right
  after.
- **A stuck startup is identifiable.** If the window is not shown within 10
  seconds a `state=timeout` record names the last completed phase; if the Dart
  UI isolate heartbeat stops for more than 10 seconds a `dart_stalled` record
  names the phase and step it stalled in. The diagnostic summary gains a
  startup timeline section.
- **A normal start costs nothing extra.** The UI isolate reports a heartbeat
  every 2 seconds, writing only native atomic variables — no disk, no log — and
  stops at `ready`. A normal cold start only adds one `boot timeline` record.

## Window size: the content area is the single contract

- **The minimum content area is 1108×772** (approximately a 1108×796 frame on
  macOS). Layout acceptance is now measured on content, not on the window
  frame.
- **Windows no longer gets a smaller content area.** Configuring a 1108×796
  *frame* left about 16×39 to the title bar and borders, so the actual content
  area fell below the accepted value and the smallest window could clip or
  scroll. The frame minimum is now derived from the non-client area measured at
  runtime, giving all three platforms the same content area.
- **The first frame is the final size.** The Windows, macOS and Linux native
  runners create the window at the 1108×772 content size directly instead of
  starting at 1280×720 or 800×600 and resizing afterwards, removing a surface
  recreation at startup.
- **The last window size is remembered.** The normal-state content size is
  saved and restored on the next start; maximized, full-screen and minimized
  sizes are ignored, and a restored size is clamped to the primary display's
  work area. A resize still waiting on its debounce is written before exit.

## Release asset verification

- **Every release now publishes `SHA256SUMS.txt`** and lists the same SHA-256
  fingerprints at the top of the release notes. After downloading, check them
  with `sha256sum -c SHA256SUMS.txt` (Linux),
  `shasum -a 256 -c SHA256SUMS.txt` (macOS) or
  `Get-FileHash -Algorithm SHA256` (Windows).
- A fingerprint only proves the downloaded file matches what was published. It
  is **not a code signature** and does not prove who built the package. The
  README documents the same commands.

## Known Limitations (Alpha)

- **Preview only.** Treat 0.3.0-alpha02 as a test build; use `0.2.1` for real
  contest logging.
- **No downgrade.** The database is migrated to schema v7. A `0.2.x` build may
  refuse to open a database written by this alpha, and QSOs logged here should
  be exported/backed up before switching back.
- **Old recordings cannot prove ownership.** Session replay requires the
  run-start header added in 0.3.0. A pending replay armed from a `0.2.1` or
  earlier recording is refused and the run starts from the current settings.
- **No online leaderboard.** Score submission and the server-side replay
  verification described in the design notes are not part of this alpha.
- **Installers are unsigned** (see below).
- Linux packages require glibc 2.35 or newer.

## Platforms and Installation

Only desktop platforms are packaged for release: Windows x64, macOS universal
(Apple Silicon and Intel), and Linux x86_64 (glibc 2.35+).

The installers are **unsigned**:

- **Windows** may warn about an unknown publisher — choose *More info → Run
  anyway*.
- **macOS** — right-click the app and choose *Open*, or allow it under
  *System Settings → Privacy & Security*.
