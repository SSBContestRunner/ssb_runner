# SSB Runner 0.3.0 Release Notes

Version: `0.3.0+300009`

This is the first stable release since `0.2.1`. It brings the A Console
interface, four interface languages, pause/resume for training runs, per-QSO
voice replay, a fixed incoming accent, a reworked function-key model and an
audio output monitor that warns when the call cannot be heard. It also
replaces the Windows zip-only distribution with a single-file installer,
states the real operating-system floors and fixes the startup, shutdown and
installer problems found in the 0.3.0 previews.

**This release changes local data formats**: the database is migrated to
schema v7 and new session recordings start with a self-describing run-start
header. Existing QSO history is migrated in place, but there is no downgrade
path: a `0.2.x` build may refuse to open a database written by `0.3.0`.

Upgrading from `0.2.1` keeps your settings and training history. Upgrading
from a 0.3.0 preview needs no extra step if it was installed from
`0.3.0-alpha07` or later; uninstall first if you still have `0.3.0-alpha06`
or earlier, because the default Windows install folder changed from
`Programs\SSB Runner` to `Programs\SSB_Runner`.

## New Console and Languages

- **The desktop UI is rebuilt as the A Console layout**: top bar, log card,
  single-row console, session card, contest rules card and a four-tab settings
  drawer, replacing the fixed sidebar and keypad.
- **Light and dark themes use the "clear sky" palette**, with Iosevka for
  data, Noto Sans SC for Chinese/Japanese, tabular numerals and a persisted
  theme choice. Every glyph the UI renders is bundled, so text no longer
  falls back to a platform font with a different weight.
- **The interface is available in English, Simplified Chinese, Traditional
  Chinese and Japanese**, following the system language by default with a
  persisted manual override. Contest names and radio abbreviations stay
  untranslated.
- **Contest rules are available in-app** from the Contest settings section
  header, including while a run is in progress.
- **The minimum content area is 1108×772** on every desktop platform. The
  native runners create the window at that size directly, and the last normal
  window size is remembered across restarts.
- **The start gate explains what is missing.** Blocking settings are listed
  with their drawer path, and tapping one opens the owning settings tab with
  the field focused. A ready/running/pending chip in the session card shows
  the same status at a glance.

## Training: Pause, Resume and Replay

- **A timed run can now be paused instead of abandoned.** Pausing freezes the
  clock, input, retry timers and audio in place; a 3-2-1 countdown (skippable)
  resumes from the same point, and answered questions are kept.
- **Pause time is not practice time.** The review reports paused duration and
  pause count separately from effective practice time.
- **The paused console is read-only.** Typing, paste and IME input are blocked
  while paused, drafts are kept, and "End session" stays available with a
  confirmation. Enter, Esc, Space, `;`, F1–F12 and quit are handled explicitly
  so a paused run cannot be lost silently.
- **Corrected QSOs can be replayed with their original audio.** Each QSO now
  stores the accent and phonetic directories it was sent with, so the
  correction list plays the exact exchange instead of regenerating it. Legacy
  QSOs without that data are marked and cannot be replayed.
- **Replay is last-wins and never disturbs a run**: repeated clicks interrupt
  the previous clip, and all replay entry points are hidden while a run is
  running or paused.
- **Session replay verifies contest ownership.** Arming a replay stores the
  recorded contest/mode/difficulty/seed snapshot; a recording without the new
  run-start header, or one that does not match, is refused and the run starts
  from the current settings.

## Listening Practice and Scoring

- **Incoming audio can be pinned to one accent** — US, UK, JP, RU or IN — or
  left on the DXCC-based **Auto** behaviour. The choice is resolved into an
  immutable policy at run start, so changing it mid-session cannot alter
  playback. The operator's own voice stays neutral Global.
- **A busted callsign is charged 2× its QSO point value** in every contest; a
  wrong exchange is NIL only, and duplicates remain free. JIDX has no official
  penalty clause, so its 2× rule is a training convention.
- **Wrong copies are logged instead of rejected.** A mis-copied call no longer
  drops the pile-up or silences the round: the QSO runs to completion, the
  review shows both the copied and the correct value, and retries and timeouts
  remain audible.
- **`;` advances every QSO phase it is valid in** and shows a hint when it is
  not. F5 repeats from the serial-waiting states as well.
- **DXCC slash calls and exact tokens resolve before the regex**, improving
  prefix handling for portable and special-event callsigns.

## Function Keys

- **Bindings are key-centric F1–F12** with explicit `Spare` slots, replacing
  the old action-centric model; existing bindings are migrated once on first
  launch.
- **Conflicts are resolved and explained.** Duplicate actions keep the lowest
  F key and the rest become `Spare`; invalid actions are cleared; occupied
  actions are greyed out with an "already used by Fx" note.
- **F12 wipes only the operator input** — no audio, state change, QSO write or
  log entry. Function keys and fixed shortcuts accept bare keys only and
  ignore Ctrl/Alt/Meta/Shift.
- **F1 abandons an in-flight QSO and requeues the station**, fixing the round
  that could loop forever in `HeAskForExchange`.
- **Phase hints appear at Beginner difficulty only** and name Enter/Esc plus
  on-screen actions instead of hardcoded F keys, so rebinding never makes a
  hint point at the wrong control.

## Audio Output Monitoring

- **A resident monitor watches the whole output chain**: CoreAudio on macOS,
  WASAPI on Windows, `pactl`/`wpctl` on Linux, plus the SoLoud engine state.
  A topbar badge appears only while something is wrong.
- **Four faults are recognised**: muted output, volume below 10 %, no output
  device, and an engine that never initialised. Low volume and mute have
  different icons. A reading that cannot be taken stays "unknown" rather than
  claiming healthy output.
- **Notifications are debounced**: hard faults show immediately; entering
  low volume and leaving any alert wait for a 600 ms quiet window or two
  consecutive polls, so dragging the volume slider does not make the badge
  flicker. Sampling runs at idle priority with a 300 ms event throttle.
- **Pre-flight before RUN shows the reason, volume and device** with *Check
  again*, a shortcut to system sound settings and *Start anyway*. Only low
  volume can be dismissed permanently.
- **A running session is never interrupted**: faults appear as one non-modal
  toast per reason per session, without taking focus or pausing the clock.
  The start button is guarded against double starts.
- **Settings offer "Play test sound"** at the recording's own level, with a
  generated-tone fallback and explicit playing/failed feedback.
- `SSB_RUNNER_DISABLE_AUDIO=1` turns the monitor off for troubleshooting.

## Startup, Exit and Diagnostics

- **The window appears straight into the loading view.** `main()` no longer
  reads files or awaits platform channels before the first frame; logging,
  preferences, the database, DXCC prefixes and audio start after it. Logs
  written before the first frame are buffered and replayed with their
  original timestamps.
- **A Windows startup timeline is recorded** from process start through
  `wWinMain`, Dart `main`, first frame and window shown, with a 10 s timeout
  and a UI-isolate heartbeat. Stalls are named in `latest.log` and in the
  diagnostic summary.
- **The MSVC runtime now comes from the build toolchain.** An older copy
  checked into the repository crashed alpha builds before the first frame on
  Windows; the packaged version is now asserted against the compiler version.
- **Closing the window no longer leaves a background process.** The exit path
  waits for an in-flight audio initialisation, always disposes the engine and
  only acknowledges the close from a definite state. A native 5 s watchdog
  covers a hang inside `ExitProcess` itself.
- **Every release publishes `SHA256SUMS.txt`** and the same fingerprints at
  the top of the release notes. A fingerprint proves the bytes match what was
  published; it is not a code signature.

## Windows Installer

- **Windows now ships a single-file Inno Setup installer** alongside the
  portable zip. It installs per user under `%LOCALAPPDATA%\Programs\SSB_Runner`
  without elevation and writes Start menu and uninstall entries.
- **The wizard is available in English, Simplified Chinese, Traditional
  Chinese and Japanese**, picks the system language automatically, shows the
  app logo, and no longer offers or creates a "launch at startup" shortcut.
- **An over-install now says what it overwrites.** A page appears only when a
  previous install is detected, showing installed → incoming version, the
  real target folder and a note that settings and training records live
  outside it and are kept. Reinstalling the same version explicitly states
  that files will be rewritten and overwritten. Silent installs are
  unaffected.
- **Downgrades are refused** before the wizard starts: an older package
  cannot replace a newer install, interactively or in silent mode. There is
  no "continue anyway", because database migrations only go forward.
- **Stale files are removed on over-install**: DLLs and `data\` are deleted
  before the new files are written, while `db\` and `log\` are excluded so
  training records and logs are never touched.

## Under the Hood

- Flutter upgraded to 3.47.9 (Dart 3.13.7) and resolvable dependencies to
  their latest versions; `window_manager` 0.6 uses its native API.
- Database schema v7 adds per-QSO accent/phonetic columns; v6 refreshes the
  DXCC prefix cache. The callsign pool and prefix table were regenerated.
- Windows 10 1607, macOS 13 and glibc 2.35 are now declared and enforced by
  CI, including an import-table guard against raising the Windows floor
  through a dependency update.
- Packaging contracts and three-platform dry runs now execute ISCC,
  dpkg-deb, appimagetool and appdmg before merge instead of only at tag time.
  CI compiles all three native runners on pull requests and retries only
  transient packaging failures.
- `flutter analyze --fatal-infos` gates info-level lints, and the test suite
  no longer emits drift's multi-instance warnings.

## Known Limitations

- **No downgrade.** The database is migrated to schema v7; back up or export
  QSO history before switching back to `0.2.x`.
- **Old recordings cannot prove ownership.** A pending replay armed from a
  `0.2.1` or earlier recording is refused and the run starts from the current
  settings.
- **No online leaderboard.** Score submission and server-side replay
  verification described in the design notes are not part of this release.
- **Supported systems**: Windows 10 version 1607 (build 14393) or later,
  macOS 13 Ventura or later, Linux with glibc 2.35 or later. Windows 10
  1507/1511, macOS 12 and older distributions are not supported. On 1607 the
  process is DPI-unaware, so at 125 %/150 % the UI is bitmap-stretched;
  per-monitor scaling starts with 1703.
- **Audio warnings depend on the platform probe.** If the system exposes
  neither volume, mute nor a default device, the badge stays silent by
  design. Linux needs `pactl` (PulseAudio/PipeWire) or `wpctl`; macOS checks
  the default output device only. Intel macOS support is best-effort.
- **Installers are unsigned** (see below).

## Platforms and Installation

Only desktop platforms are packaged: Windows x64, macOS universal (Apple
Silicon and Intel) and Linux x86_64.

- **Windows** — `*windows-setup.exe` (per user, no elevation; refuses Windows
  older than 10 1607) or `*windows.zip`.
- **macOS** — `*macos.dmg`; drag **SSB Runner.app** into *Applications*.
- **Linux** — `.deb`, `.AppImage` and `.zip`; all require glibc 2.35+. The
  AppImage needs FUSE 2 to mount, or run it with
  `--appimage-extract-and-run`.

The installers are **unsigned**:

- **Windows** may warn about an unknown publisher — choose *More info → Run
  anyway*.
- **macOS** — right-click the app and choose *Open*, or allow it under
  *System Settings → Privacy & Security*.
