# SSB Runner 0.3.0-alpha07 Release Notes

Version: `0.3.0+300007`

**This is still an alpha preview of 0.3.0, not a stable release.** It fixes the
Windows startup crash reported in issue #71 on Windows 10 RTM, and states the
real Windows floor: **Windows 10 version 1607 (build 14393) or newer**. The
database schema and the event-log format are unchanged, so training history and
settings survive the upgrade as is.

## Windows: Windows 10 10240 no longer fails at startup

- **Symptom.** On Windows 10 RTM (build 10240, also 10586) the window appeared,
  then the app switched to the startup-failure page and reported an
  `ArgumentError`: `Failed to load dynamic library 'cnativeapi.dll'` with
  `error code: 127` (`The specified procedure could not be found`). Nothing was
  logged to explain it.
- **Cause.** `window_manager` 0.6 resolves windows through
  nativeapi/cnativeapi, whose DLL statically imports
  `user32!GetDpiForWindow`. That API only exists from Windows 10 version 1607
  (build 14393), so on 1507/1511 the DLL cannot be loaded at all and every
  window call throws. Window geometry was treated as required, which turned
  "optional capability unavailable" into a fatal startup error and a crash
  report.
- **Fix (portable zip).** The native startup path now checks for the API and
  loads `cnativeapi.dll` once before the Flutter engine starts. If either step
  fails, the app shows a bilingual message that names Windows 10 1607 / build
  14393 as the requirement and exits cleanly: no crash report, no hidden
  process, no half-started window.
- **Fix (installer).** The installer now declares `MinVersion=10.0.14393`, so
  Inno Setup refuses older systems with its own "Windows version not supported"
  page instead of installing an unusable copy.
- **Fix (app).** Window resolution is fail-soft: it returns "no window" instead
  of throwing, geometry restore and resize tracking are skipped when no window
  can be reached, and the first frame still proceeds to the normal startup
  flow. If window management is unavailable, startup now shows a warning toast
  instead of a failure page.

## Windows: the minimum OS version is now guarded in CI

- The Windows package job parses the import table of every `.dll` and `.exe` in
  the packaged `Release/` directory and fails if a binary imports an API newer
  than Windows 10 1607, unless that API is on a short allow-list
  (`GetDpiForWindow`, `AdjustWindowRectExForDpi`, both from cnativeapi and both
  covered by the native pre-check). A dependency upgrade can no longer raise the
  real OS floor unnoticed.
- Tool: `dart run tool/check_windows_imports.dart <Release directory>`. It runs
  on any OS, so the check can be reproduced without a Windows machine.

## Support matrix

- Windows: **Windows 10 version 1607 (build 14393) or later, or Windows 11**.
  On 1607 the process is DPI-unaware, so at 125%/150% the UI is bitmap-stretched;
  per-monitor scaling starts with 1703. Windows 10 1507/1511 is not supported.
