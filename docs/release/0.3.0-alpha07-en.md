# SSB Runner 0.3.0-alpha07 Release Notes

Version: `0.3.0+300007`

**This is still an alpha preview of 0.3.0, not a stable release.** The headline
is an audio output check: the app now tells you when you cannot hear the call
audio — muted output, a nearly silent volume, no output device, or an engine
that never started — instead of letting you run a whole session in silence. The
release also states the real OS floors (Windows 10 1607, macOS 13, glibc 2.35),
fixes the Windows 10 startup crash from issue #71, ships the missing Chinese
glyphs, and polishes the Windows installer. The database schema and the event-log
format are unchanged, so training history and settings survive the upgrade as
is. Use `0.2.1` if you are logging a real contest.

Upgrading from `0.3.0-alpha06` is a plain over-install, except for one Windows
detail: the installer now targets
`%LOCALAPPDATA%\Programs\SSB_Runner` (no space), so uninstall the old copy
first, otherwise two installations coexist.

## Audio output monitoring: warn when the call cannot be heard

- **A resident monitor now watches the whole output chain.** On macOS it reads
  volume, mute and the default device through CoreAudio, on Windows through
  WASAPI, and on Linux through `pactl` or `wpctl`; it also polls the SoLoud
  engine state. A topbar badge appears only while something is wrong, so a
  healthy output stays invisible.
- **Four faults are recognised**: muted output, volume below 10 %, no output
  device, and an engine that did not initialise. Low volume and mute now use
  different icons — a quiet output is no longer drawn as a crossed-out speaker.
- **A reading that cannot be taken is treated as unknown, never as healthy.**
  Platforms without a probe stay silent rather than warning wrongly, and a
  failed read holds the current state instead of clearing an alert the probe can
  no longer see.
- **Notifications are debounced.** Mute, no device and engine-down are hard
  states and show immediately; entering the low-volume state and *leaving* any
  alert wait for a 600 ms quiet window (on system events) or two consecutive
  polls (on the fallback timer), so dragging the volume slider does not make the
  badge flicker.
- **Polling is cheap**: 2 s while the window is visible, 10 s while it is hidden
  (3 s on Linux, where each sample forks `pactl`). It runs on `Priority.idle`,
  event-driven samples are throttled to one per 300 ms, the per-sample
  `listPlaybackDevices()` FFI call is gone (device existence comes from the
  platform's default endpoint), and on Linux volume and mute are read with a
  single `pactl` JSON call. In debug builds a sample that spends more than 8 ms
  logs once per slow streak, timing the platform round-trip separately so a
  stalled CoreAudio read is visible too.
- `SSB_RUNNER_DISABLE_AUDIO=1` turns the monitor off, for troubleshooting.

## Running a session: pre-flight and in-session warnings

- **RUN now goes through a pre-flight dialog for any fault**, showing the
  reason, the current volume and the device name, with *Check again* and a
  shortcut to the system sound settings. Starting is always possible through
  *Start anyway*, and a re-check that turns healthy closes the dialog and
  continues by itself.
- **Only low volume can be dismissed permanently**, with *Don't warn about low
  volume* in that dialog or the matching switch in settings, which is on by
  default.
- **A running session is never interrupted.** The fault is repeated as a
  non-modal toast — one per reason per session, re-armed after recovery — that
  takes no focus and never pauses the clock.
- The start button is guarded against a double click, so two sessions can no
  longer start from one double-tap.

## Settings: play a test sound

- **A "Play test sound" row plays a short sample at the recording's own level**,
  so you can set the system volume before the clock starts. It falls back to a
  generated tone if the sample cannot be loaded.
- The row reports *Playing…* and *Audio playback failed* instead of failing
  silently.

## Windows: Windows 10 10240 no longer fails at startup

- **Symptom.** On Windows 10 RTM (build 10240, also 10586) the window appeared,
  then the app switched to the startup-failure page and reported an
  `ArgumentError`: `Failed to load dynamic library 'cnativeapi.dll'` with
  `error code: 127` (`The specified procedure could not be found`). Nothing was
  logged to explain it.
- **Cause.** `window_manager` 0.6 resolves windows through
  nativeapi/cnativeapi, whose DLL statically imports
  `user32!GetDpiForWindow`. That API only exists from Windows 10 version 1607
  (build 14393), so on 1507/1511 the DLL cannot be loaded at all and every
  window call throws. Window geometry was treated as required, which turned
  "optional capability unavailable" into a fatal startup error and a crash
  report.
- **Fix (portable zip).** The native startup path now checks for the API and
  loads `cnativeapi.dll` once before the Flutter engine starts. If either step
  fails, the app shows a bilingual message that names Windows 10 1607 / build
  14393 as the requirement and exits cleanly: no crash report, no hidden
  process, no half-started window.
- **Fix (installer).** The installer now declares `MinVersion=10.0.14393`, so
  Inno Setup refuses older systems with its own "Windows version not supported"
  page instead of installing an unusable copy.
- **Fix (app).** Window resolution is fail-soft: it returns "no window" instead
  of throwing, geometry restore and resize tracking are skipped when no window
  can be reached, and the first frame still proceeds to the normal startup
  flow. If window management is unavailable, startup now shows a warning toast
  instead of a failure page.

## macOS: the floor is 13 Ventura, not 12

- **macOS 12 cannot run this build and now says so.** Flutter 3.47 compiles the
  native assets (sqlite3, cnativeapi, flutter_soloud, objective_c) with a fixed
  macOS 13 deployment target, and dyld refuses to load them on 12 even though
  Flutter itself allows it. `MACOSX_DEPLOYMENT_TARGET` and the README now state
  the floor the bundle actually has, so a 12.x user gets the documented
  requirement instead of a launch failure. The previous "macOS 12 Monterey"
  claim was wrong.

## Linux: the glibc 2.35 floor is now enforced

- **The AppImage was quietly baking in a newer glibc.** It copies the build
  runner's `libstdc++` and `libgcc_s` into `usr/lib`, which is how `GLIBC_2.35`
  got in unnoticed: the smoke test only checked the Debian 12 container, where
  everything resolves.
- **The check now inspects the extracted AppImage, including `usr/lib`**,
  against the declared 2.35 / `GLIBCXX_3.4.30` floor, and launches it under
  Xvfb like the `.deb`, so the packaged runtime is exercised instead of
  assumed.
- **The image is also smaller**: the ~24 MB `libjvm.so` that the Android-only
  `libdartjni.so` dragged in is dropped from the AppImage.
- The AppImage still bundles `libstdc++` and `libgcc`, but not glibc. Mounting
  it needs FUSE 2, which recent distributions no longer install by default;
  without it, run the file with `--appimage-extract-and-run`.

## Windows installer: layout and install path

- **The wizard logo no longer touches the window edges.** Inno draws
  `WizardSmallImageFile` flush against the client area's top-right corner and
  `[Setup]` has no margin directive, so the tile touched the title bar and the
  right border. All three DPI variants now bake in a uniform 10 % transparent
  inset; canvas sizes stay unchanged, so the header title and subtitle do not
  shift.
- **The default install folder is `Programs\SSB_Runner`, without the space.**
  Spaces in the install directory invite quoting and tooling edge cases on
  Windows. The display name is unchanged, so shortcuts still read
  "SSB Runner". The product has not shipped, so no migration is provided — an
  old alpha stays in `Programs\SSB Runner` until it is uninstalled.

## Fonts: every glyph the UI renders is shipped

- **The Chinese font fallback is gone.** The bundled Noto Sans SC subsets were
  generated before the pause and replay strings landed, so characters such as
  结/束/暂/继/续 fell back to the platform CJK font per glyph. On Windows that
  is Microsoft YaHei, which has no Medium weight, so *结束本局* was rendered in
  two typefaces and two weights on one line.
- **The subsets are rebuilt from the full UI inventory** with
  `tool/build_fonts.py` (Noto Sans SC 2.004, Iosevka 34.9.1), and a cmap-level
  coverage test now fails the suite when UI text drifts outside the shipped
  fonts.

## Packaging and CI hardening

- **Native Windows code is now compiled on every PR and branch push.** It
  previously had no gate until a tag was pushed, which is how a `C3668` on an
  audio COM destructor reached a release run. The destructor is declared
  `virtual` instead.
- **`appimagetool` is pinned by SHA-256**, the trim script normalises the
  extracted AppDir modes (build 370 treats `0700` directories as fatal), and it
  now asserts that the repacked image exists and shrank instead of silently
  keeping `libjvm.so`.
- **Only transient packaging failures are retried.** A real compiler diagnostic
  (`error C####`) fails immediately, while "Build process failed." still
  retries the known transient native-assets failure.
- **A CI import-table guard protects the Windows floor.** The package job
  parses every `.dll` and `.exe` in `Release/` and fails on an import newer than
  Windows 10 1607, unless it is on a short allow-list (`GetDpiForWindow`,
  `AdjustWindowRectExForDpi`, both from cnativeapi and both covered by the
  native pre-check). A dependency upgrade can no longer raise the real OS floor
  unnoticed. Reproduce it with
  `dart run tool/check_windows_imports.dart <Release directory>`; it runs on any
  OS.

## Known Limitations (Alpha)

- **Preview only.** Treat 0.3.0-alpha07 as a test build; use `0.2.1` for real
  contest logging.
- **Supported systems**: Windows 10 version 1607 (build 14393) or later, macOS
  13 Ventura or later, Linux with glibc 2.35 or later. Windows 10 1507/1511,
  macOS 12 and older distros are not supported; on 1607 the process is
  DPI-unaware, so at 125 %/150 % the UI is bitmap-stretched (per-monitor scaling
  starts with 1703).
- **Audio warnings depend on the platform probe.** If the system exposes
  neither volume, mute nor a default device, the badge stays silent by design.
  Linux support requires `pactl` (PulseAudio/PipeWire) or `wpctl`; macOS uses the
  default output device only.
- **No downgrade.** The database is migrated to schema v7. A `0.2.x` build may
  refuse to open a database written by this alpha, and QSOs logged here should
  be exported/backed up before switching back.
- **Old recordings cannot prove ownership.** Session replay requires the
  run-start header added in 0.3.0. A pending replay armed from a `0.2.1` or
  earlier recording is refused and the run starts from the current settings.
- **No online leaderboard.** Score submission and the server-side replay
  verification described in the design notes are not part of this alpha.
- **Installers are unsigned** (see below).

## Platforms and Installation

Only desktop platforms are packaged for release: Windows x64, macOS universal
(Apple Silicon and Intel), and Linux x86_64.

- **Windows** — `*windows-setup.exe` (per user, no elevation; refuses Windows
  older than 10 1607) or `*windows.zip`. On 1607 the process is DPI-unaware, so
  at 125 %/150 % the UI is bitmap-stretched; per-monitor scaling starts with
  Windows 10 1703.
- **macOS** — `*macos.dmg`, drag **SSB Runner.app** into *Applications*.
  Requires macOS 13 Ventura or later; Intel support is best-effort.
- **Linux** — `.deb`, `.AppImage` and `.zip`; all three require glibc 2.35+.
  The AppImage needs FUSE 2 to mount, or run it with
  `--appimage-extract-and-run`.

The installers are **unsigned**:

- **Windows** may warn about an unknown publisher — choose *More info → Run
  anyway*.
- **macOS** — right-click the app and choose *Open*, or allow it under
  *System Settings → Privacy & Security*.
