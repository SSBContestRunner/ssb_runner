# SSB Runner 0.3.0-alpha08 更新说明

版本：`0.3.0+300008`

**本版本仍是 0.3.0 的 alpha 预览版，不是稳定版。** 本版没有应用功能变更，改动集中在 Windows 安装器与打包流程：覆盖安装时会明确说明"装到哪个目录、会覆盖哪个版本、数据不会被动"，旧安装包覆盖新版本会被直接拒绝，残留的旧 DLL 不再与新文件混装；同时补上了打包验证层，让 Inno Setup、dpkg-deb、appimagetool、appdmg 在合并前就真的执行一遍，而不是等到打 tag。**数据库结构与事件日志格式都没有变化**，升级后训练记录与设置原样保留；如果要记录真实比赛，请继续使用 `0.2.1`。

从 `0.3.0-alpha07` 升级可以直接覆盖安装。如果从 `0.3.0-alpha06` 或更早的版本升级，请先卸载旧版本：`alpha07` 把安装目录从 `Programs\SSB Runner` 改成了 `Programs\SSB_Runner`，不卸载会并存两份安装。

## Windows 安装器：覆盖安装会说明自己在覆盖什么

- **新增"覆盖安装"页面**，只在检测到既有安装时出现，位置正好是被 Inno 静默跳过的"选择目标位置"页之后。页面显示已安装版本 → 本次安装包版本、真实的目标目录，以及"设置与训练记录保存在用户数据目录，不会被删除"。
- **显示的是真实写入目录，不是配置里的默认目录。** 目标目录取向导实际使用的路径，因此当旧安装位于不同文件夹时（例如 `alpha06` 的 `Programs\SSB Runner`），页面显示的是即将被写入的那个旧文件夹，而不是新包的默认值。
- **同版本重装会明确说明**"当前已是该版本，安装将重新覆盖写入"，不再与全新安装看起来一模一样。
- **静默安装路径完全不变**：应用内更新使用的 `/VERYSILENT` 流程不会看到新页面，也不会多出任何弹框。
- **检测依据**是 per-user 卸载项里的 `DisplayVersion`，目录回落到 `Inno Setup: App Path` / `InstallLocation`；若目录存在但版本值缺失，仍按"覆盖安装"处理。

## 降级被明确拒绝

- **旧安装包不能再静默覆盖新版本。** 当已安装版本高于本安装包时，安装器在向导创建之前就中止：交互模式下弹一次"无法继续安装"并在说明里给出两个版本号，静默模式下只写日志并以非零码退出。两种情况都不会修改安装目录。
- **没有"强制继续"入口。** 数据库迁移只有向前的分支（当前 schema v7），旧版本读到更高版本的数据库行为未定义，因此降级一律不允许。

## 覆盖安装不再新旧文件混装

- **安装前清理本次一定会重写的产物**：`{app}\*.dll` 与 `{app}\data` 会在写入新文件之前删除。旧版本已经移除的 DLL、资源不会再与新文件并存。
- **`db\` 与 `log\` 被明确排除。** 应用的数据根目录在极端情况下会回落到 exe 所在目录，那里可能承载真实的训练记录与日志，因此安装器不碰这两个目录。
- **覆盖行为不再依赖 Inno 的版本默认值**：显式声明 `CloseApplications=yes`（由 Restart Manager 关闭占用待替换文件的进程，避免"写入失败但向导显示成功"）与 `RestartApplications=no`（静默更新后的重启由应用内更新负责，安装器不重复拉起）。

## 打包与 CI：打包脚本在合并前就真的跑过

- **新增打包静态契约（L0）**：对三个平台的 `make_config.yaml`、模板、CI 编排与打包器版本做静态检查，检查器本身也有 `flutter test` 用例覆盖。
- **新增三平台打包 dry run**：用 stub bundle 走一遍真实的 `flutter_app_packager` 调用，ISCC、dpkg-deb、appimagetool 与 appdmg 都会真正执行。此前直到打 tag 才有任何东西编译安装脚本，一个被折叠的 `[` 就曾让安装包构建失败。
- **dry run 与真实打包互斥**：验证任务只在 PR 与合并队列上运行，两者不再同时出现在同一次事件里。
- **Linux 与 macOS 的原生 runner 现在每次 PR 都编译**，与 Windows 对齐；三个编译任务同时注册合并队列。
- **只重试瞬时打包失败**：真正的编译器诊断（`error C####`）立即失败；Windows 打包失败时会连同渲染后的 `.iss` 一起上传，便于定位。
- **安装器冒烟测试扩展**：同一安装包连续安装两次（第二次走"同版本覆盖"路径），并把卸载项版本临时改成 `99.0.0` 验证降级阻断确实不改动安装目录。

## 已知限制（Alpha）

- **仅供预览。** 请把 0.3.0-alpha08 当作测试版本；真实比赛记录请使用 `0.2.1`。
- **支持的系统**：Windows 10 版本 1607（Build 14393）或更高版本；macOS 13 Ventura 或更高版本；glibc 2.35 或更高的 Linux。不支持 Windows 10 1507/1511、macOS 12 与更旧的发行版；1607 上进程是 DPI 不感知的，125%/150% 缩放下界面会被位图拉伸（PerMonitor 缩放从 1703 开始）。
- **音频提示依赖平台探针。** 若系统既读不到音量、静音也读不到默认设备，徽标按设计保持沉默。Linux 需要 `pactl`（PulseAudio/PipeWire）或 `wpctl`；macOS 只检查默认输出设备。
- **不可降级，现在安装器也会拦。** 数据库已迁移到 v7。`0.2.x` 版本可能无法打开本 alpha 写出的数据库，切回旧版前请先导出/备份 QSO 历史；拿旧安装包覆盖安装会被安装器直接拒绝。
- **旧录像无法证明归属。** 会话重放依赖 0.3.0 新增的开局记录头。由 `0.2.1` 或更早版本录制的待重放会话会被拒绝，并改为按当前设置开局。
- **没有在线排行榜。** 设计文档中的分数上传与服务端重放校验不在本 alpha 范围内。
- **安装包未签名**（见下文）。

## 平台与安装

仅打包桌面平台：Windows x64、macOS universal（Apple Silicon 与 Intel）、Linux x86_64。

- **Windows** — `*windows-setup.exe`（纯 per-user 安装，不弹 UAC；低于 Windows 10 1607 会拒绝安装）或 `*windows.zip`。1607 上进程 DPI 不感知，125%/150% 缩放下界面会被位图拉伸；PerMonitor 缩放从 Windows 10 1703 开始。
- **macOS** — `*macos.dmg`，把 **SSB Runner.app** 拖入 *Applications*。要求 macOS 13 Ventura 或更高版本；Intel 支持为尽力而为。
- **Linux** — `.deb`、`.AppImage` 与 `.zip`，三者都要求 glibc 2.35+。AppImage 挂载需要 FUSE 2，也可用 `--appimage-extract-and-run` 运行。

安装包**未签名**：

- **Windows** 可能提示未知发布者 — 选择 *更多信息 → 仍要运行*。
- **macOS** — 右键点击应用并选择 *打开*，或在 *系统设置 → 隐私与安全性* 中允许。
